## Por qué una lección de JavaScript en un curso de TypeScript

TypeScript **no cambia cómo se comporta JavaScript**: sólo le agrega tipos. Todo lo que se ejecuta (comparaciones,
`this`, closures, módulos) sigue las reglas de JavaScript. Muchos errores de quienes vienen de C# o Java no son de
tipos sino de semántica de JavaScript: `this` que se pierde, `||` que pisa un `0`, objetos comparados por
referencia.

Esta lección es una referencia rápida de la sintaxis que vas a ver en todo el curso. Si algo ya lo conocés, salteá
esa sección.

## Variables y alcance

```ts
const maxRetries = 3; // no se puede reasignar
let attempt = 0; // se puede reasignar
attempt += 1;

const student = { name: "Ana" };
student.name = "Ana María"; // ✅ const impide reasignar la variable, no mutar el objeto
// student = { name: "Luis" }; ❌ Error: no se puede reasignar una constante
```

- **`const` por defecto, `let` cuando necesitás reasignar.** Es la convención de prácticamente todos los equipos.
- `const` es como `final` en Java o `readonly` local: **la referencia es fija, el objeto no es inmutable**.
- Ambos tienen **alcance de bloque** (`{ ... }`), igual que en C# y Java.
- **`var` no se usa más:** tiene alcance de función y se "eleva" (hoisting) al principio de la función, lo que
  produce bugs sutiles. Si lo ves, es código viejo.

## Igualdad y valores truthy/falsy

```ts
1 === 1; // true
"1" === 1; // false: tipos distintos, sin conversión
"1" == 1; // true: == convierte tipos (coerción). Por eso no se usa.

[1, 2] === [1, 2]; // false: dos arrays distintos (referencias distintas)
{ id: 1 } === { id: 1 }; // false, por la misma razón
```

**Regla:** usá siempre `===` y `!==`. La única excepción aceptada es `value == null`, que es `true` para `null` y
para `undefined` a la vez. Los objetos y arrays **se comparan por referencia**, como las clases en C# y Java (no hay
`Equals` sobrescribible).

En una condición (`if`, `while`, `&&`, `||`, `!`) cualquier valor se convierte a booleano:

| Falsy (se comporta como `false`)                           | Truthy (todo lo demás)                                       |
| ---------------------------------------------------------- | ------------------------------------------------------------ |
| `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN` | `"0"`, `"false"`, `[]`, `{}`, cualquier número distinto de 0 |

```ts
function describeBalance(balanceCents: number | undefined): string {
  if (!balanceCents) return "Sin saldo"; // ❌ trata un saldo de 0 igual que "no hay dato"
  return `Saldo: ${balanceCents}`;
}

function describeBalanceFixed(balanceCents: number | undefined): string {
  if (balanceCents === undefined) return "Sin dato"; // ✅ distingue ausencia de cero
  return `Saldo: ${balanceCents}`;
}
```

## Strings y template literals

```ts
const name = "Ana";
const grade = 8.5;
const message = `Hola ${name}, tu nota final es ${grade}`; // interpolación con backticks
const multiline = `Línea 1
Línea 2`;
```

Comillas simples y dobles son equivalentes. Los backticks permiten interpolar y escribir varias líneas, como `$"..."`
en C# o los text blocks de Java.

## Funciones y this

Hay dos sintaxis principales:

```ts
// Declaración de función: tiene nombre y se puede usar antes de su definición (hoisting)
function add(a: number, b: number): number {
  return a + b;
}

// Arrow function: expresión, ideal para callbacks
const multiply = (a: number, b: number): number => a * b;
const square = (x: number) => x * x; // retorno implícito con una sola expresión
const toEntry = (id: string) => ({ id, createdAt: Date.now() }); // para devolver un objeto, entre paréntesis
```

Las funciones son **valores**: se guardan en variables, se pasan como argumentos y se devuelven. Una función
recuerda las variables del lugar donde fue creada (**closure**), igual que las lambdas de C# y Java, pero sin la
restricción de Java de que sean _effectively final_.

```ts
function createCounter() {
  let count = 0;
  return () => ++count; // la arrow function "recuerda" count
}

const next = createCounter();
next(); // 1
next(); // 2
```

### Parámetros opcionales, por defecto y rest

```ts
function sendReminder(studentId: string, channel: "sms" | "email" = "email", note?: string): void {
  // note puede ser undefined
}

function sumAll(...values: number[]): number {
  return values.reduce((acc, value) => acc + value, 0); // como params en C# o varargs en Java
}
```

### this: la mayor diferencia con C# y Java

En C# y Java, `this` siempre es la instancia de la clase. En JavaScript, **en una función normal `this` depende de
cómo se llama a la función**, no de dónde se definió. Una arrow function, en cambio, **no tiene `this` propio**: usa
el del contexto donde se creó.

```ts
class ReminderScheduler {
  private sent = 0;

  // ❌ Método normal usado como callback: this se pierde
  markSent() {
    this.sent++;
  }

  // ✅ Propiedad con arrow function: this queda fijo en la instancia
  markSentSafe = () => {
    this.sent++;
  };
}

const scheduler = new ReminderScheduler();
const ids = ["c1", "c2"];
ids.forEach(scheduler.markSent); // TypeError: Cannot read properties of undefined
ids.forEach(scheduler.markSentSafe); // ✅
ids.forEach(() => scheduler.markSent()); // ✅ también: se llama como método
```

## Objetos: atajos, destructuring y spread

```ts
const id = "enr_1";
const courseId = "typescript-101";

const enrollment = { id, courseId, status: "active" }; // atajo: { id: id, courseId: courseId }

// Destructuring: extraer propiedades en variables
const { status, courseId: course } = enrollment; // renombra courseId a course

// Destructuring en parámetros, muy común en funciones con muchas opciones
function enroll({ studentId, courseId }: { studentId: string; courseId: string }) {
  return { studentId, courseId };
}

// Arrays también se desestructuran
const [first, second, ...rest] = [10, 20, 30, 40]; // rest = [30, 40]

// Spread: copiar y combinar sin mutar (copia superficial)
const completed = { ...enrollment, status: "completed", completedAt: "2026-11-19" };
const allGrades = [...[7, 8], ...[9, 10]];
```

`{ ...enrollment, status: "completed" }` es el equivalente idiomático de un `with` sobre un `record` de C#: crea un
objeto nuevo con una propiedad cambiada. Es la base de la inmutabilidad en React y en reducers.

<Callout type="warning" title="Spread copia un solo nivel">
  `{...enrollment}` copia las propiedades del primer nivel. Si `enrollment.student` es un objeto, la copia y
  el original comparten la misma referencia. Para una copia profunda de datos simples existe
  `structuredClone(enrollment)`.
</Callout>

### Optional chaining y nullish coalescing

```ts
interface Student {
  name: string;
  contact?: { email?: string; phone?: string };
}

function preferredChannel(student: Student): string {
  // ?. corta y devuelve undefined si lo de la izquierda es null o undefined
  const email = student.contact?.email;
  // ?? usa el valor de la derecha sólo si la izquierda es null o undefined
  return email ?? student.contact?.phone ?? "sin contacto";
}

const retries = 0;
retries || 3; // 3 ❌: 0 es falsy y || lo descarta
retries ?? 3; // 0 ✅: ?? sólo reemplaza null y undefined
```

Son los mismos operadores `?.` y `??` de C#. En Java el equivalente es encadenar `Optional`.

## Arrays y sus métodos funcionales

```ts
interface Assignment {
  number: number;
  grade: number;
  submitted: boolean;
}

const assignments: Assignment[] = [
  { number: 1, grade: 9, submitted: true },
  { number: 2, grade: 7, submitted: true },
  { number: 3, grade: 0, submitted: false },
];

const delivered = assignments.filter((a) => a.submitted); // Where
const grades = delivered.map((a) => a.grade); // Select
const average = grades.reduce((acc, value) => acc + value, 0) / grades.length; // Aggregate
const firstMissing = assignments.find((a) => !a.submitted); // FirstOrDefault (o undefined)
const anyMissing = assignments.some((a) => !a.submitted); // Any
const allSubmitted = assignments.every((a) => a.submitted); // All
const ranked = assignments.toSorted((a, b) => b.grade - a.grade); // OrderByDescending, sin mutar
```

| JavaScript               | C# (LINQ)            | Java (Streams)            |
| ------------------------ | -------------------- | ------------------------- |
| `map`                    | `Select`             | `map`                     |
| `filter`                 | `Where`              | `filter`                  |
| `reduce`                 | `Aggregate`          | `reduce`                  |
| `find`                   | `FirstOrDefault`     | `filter(...).findFirst()` |
| `some` / `every`         | `Any` / `All`        | `anyMatch` / `allMatch`   |
| `flatMap`                | `SelectMany`         | `flatMap`                 |
| `toSorted`, `toReversed` | `OrderBy`, `Reverse` | `sorted`                  |

Dos diferencias importantes: los métodos de arrays son **eager** (cada `map` o `filter` crea un array nuevo, no hay
ejecución diferida como en LINQ o Streams), y **`sort`, `reverse` y `splice` mutan el array original**. Para no mutar
existen `toSorted`, `toReversed` y `toSpliced`.

Para diccionarios y conjuntos, JavaScript tiene `Map` y `Set`, equivalentes a `Dictionary` y `HashSet`:

```ts
const byStudent = new Map<string, Assignment[]>();
byStudent.set("stu_1", assignments);
byStudent.get("stu_1"); // Assignment[] | undefined

const seenEvents = new Set<string>();
seenEvents.add("evt_1");
seenEvents.has("evt_1"); // true
```

## Clases

```ts
class Exam {
  // Campo con #: privado real en runtime. private de TypeScript se borra al compilar.
  #attempts = 0;
  static readonly maxAttempts = 3;

  constructor(
    readonly courseId: string, // parameter property: declara y asigna el campo
    private closesAt: Date,
  ) {}

  get isClosed(): boolean {
    return this.closesAt.getTime() <= Date.now();
  }

  attempt(): boolean {
    if (this.isClosed || this.#attempts >= Exam.maxAttempts) return false;
    this.#attempts++;
    return true;
  }
}

class TimedExam extends Exam {
  constructor(
    courseId: string,
    closesAt: Date,
    readonly durationMinutes: number,
  ) {
    super(courseId, closesAt);
  }
}
```

Las clases existen, funcionan como esperás y soportan herencia simple, `abstract`, `implements` de interfaces,
getters y miembros estáticos. Pero en TypeScript idiomático **se usan menos que en C# o Java**: los datos se modelan
con interfaces y objetos literales, y la lógica con funciones. Las clases se reservan para cuando hay estado
encapsulado con comportamiento (un cliente HTTP, un repositorio, un caso de uso con dependencias).

## Módulos ES

Cada archivo es un módulo con su propio alcance. Lo que no se exporta es privado al archivo.

```ts
// src/grades/format.ts
export function formatGrade(grade: number): string {
  return grade.toFixed(1);
}

export const PASSING_GRADE = 6;

export default class GradeFormatter {}
```

```ts
// src/main.ts
import GradeFormatter, { formatGrade, PASSING_GRADE } from "./grades/format.js";
import * as format from "./grades/format.js"; // todo el módulo como objeto
import type { Assignment } from "./grades/types.js"; // import sólo de tipos: se borra al compilar
```

- Un módulo se parece más a un archivo con miembros `internal` que a un `namespace` o un `package`.
- **Preferí exports con nombre** sobre `export default`: se renombran con refactors y se buscan más fácil.
- `import type` deja explícito que sólo importás tipos; con `verbatimModuleSyntax` es obligatorio.
- En Node.js con ESM, los imports relativos llevan extensión (`.js`), aunque el archivo fuente sea `.ts`.
- Existe un sistema anterior, CommonJS (`require` y `module.exports`). Lo vas a ver en código de Node.js viejo; el
  curso de Node.js explica cómo conviven.

## Errores y excepciones

```ts
class CourseFullError extends Error {
  constructor(readonly courseId: string) {
    super(`El curso ${courseId} no tiene cupo`);
    this.name = "CourseFullError";
  }
}

try {
  throw new CourseFullError("typescript-101");
} catch (error) {
  // error es unknown: en JavaScript se puede lanzar cualquier valor, incluso un string
  if (error instanceof CourseFullError) {
    console.log(error.courseId);
  } else {
    throw error;
  }
} finally {
  console.log("siempre se ejecuta");
}
```

- No hay **excepciones chequeadas** como en Java ni `throws` en la firma: nada indica qué puede lanzar una función.
- No hay `catch` por tipo: se captura todo y se discrimina con `instanceof`.
- Por eso, para errores esperables del dominio, muchos equipos usan un **tipo Result** en lugar de excepciones (lo
  vemos en el módulo de diseño).

## Comparación con C# y Java

| Tema                | C#                      | Java                       | JavaScript / TypeScript                             |
| ------------------- | ----------------------- | -------------------------- | --------------------------------------------------- |
| Variable inmutable  | `readonly`, `const`     | `final`                    | `const` (sólo la referencia)                        |
| Igualdad de objetos | `Equals` sobrescribible | `equals` sobrescribible    | Sólo por referencia                                 |
| `this`              | Siempre la instancia    | Siempre la instancia       | Depende de la llamada (salvo arrow functions)       |
| Copiar con cambios  | `record with { }`       | Constructor o builder      | `{ ...obj, prop: valor }`                           |
| Null-safe           | `?.` y `??`             | `Optional`                 | `?.` y `??`                                         |
| Colecciones         | LINQ diferido           | Streams diferidos          | Métodos de arrays eager                             |
| Visibilidad         | `private`, `internal`   | `private`, package-private | `#campo` (runtime), `private` (sólo tipos), módulos |
| Excepciones         | Sin chequear            | Chequeadas y no chequeadas | Se lanza cualquier valor; `catch` recibe `unknown`  |

## Errores frecuentes

- **Usar `||` para valores por defecto numéricos.** `limit || 10` convierte un `0` legítimo en `10`. Usá `??`.
- **Comparar objetos con `===` esperando igualdad por valor.** Compará propiedades o IDs.
- **Pasar métodos como callbacks.** `promise.then(this.handle)` pierde el `this`; usá una arrow function.
- **Mutar con `sort` o `reverse`.** Ordenar un array que recibiste como parámetro lo modifica para quien te lo pasó.
- **Olvidar `await` o el `return` en una arrow function con llaves.** `items.map((i) => { i.grade })` devuelve
  `undefined` por cada elemento: con llaves hace falta `return`.
- **Lanzar strings.** `throw "error"` pierde el stack trace; lanzá siempre instancias de `Error`.
