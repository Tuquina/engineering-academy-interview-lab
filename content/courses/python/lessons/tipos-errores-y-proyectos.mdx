## Type hints

Python es dinámico, pero desde la versión 3.5 admite **anotaciones de tipo**. No cambian la ejecución: las verifican
herramientas como **mypy** o **pyright**, y las aprovechan el editor y librerías como Pydantic.

```python
from typing import Protocol, TypedDict

def find_customer(customer_id: str) -> "Customer | None":   # puede devolver None
    ...

def apply_discount(prices: list[int], pct: float) -> list[int]:
    return [round(p * (1 - pct / 100)) for p in prices]

class PaymentGateway(Protocol):                 # interfaz estructural: no hace falta heredar
    def charge(self, amount_cents: int, token: str) -> str: ...

class StripeGateway:                            # cumple el Protocol por tener el método
    def charge(self, amount_cents: int, token: str) -> str:
        ...

class OrderPayload(TypedDict):                  # forma de un diccionario
    sku: str
    quantity: int

def first[T](items: list[T]) -> T | None:       # genéricos con la sintaxis de Python 3.12
    return items[0] if items else None
```

```bash
uv run mypy --strict src/
```

`Protocol` funciona como las interfaces de TypeScript: la compatibilidad es **estructural**. Es la forma natural de
definir puertos en una arquitectura hexagonal en Python.

## Excepciones

```python
class OutOfStockError(Exception):
    def __init__(self, sku: str, requested: int):
        super().__init__(f"Sin stock suficiente de {sku} (pedido: {requested})")
        self.sku = sku

try:
    inventory.reserve(sku, quantity)
except OutOfStockError as error:
    return {"status": "rejected", "reason": str(error)}
except TimeoutError as error:
    raise CheckoutError("El inventario no respondió") from error   # conserva la causa
else:
    payments.charge(order)          # sólo si no hubo excepción
finally:
    metrics.increment("checkout.attempt")
```

Python favorece el estilo **EAFP** (_Easier to Ask Forgiveness than Permission_): intentar la operación y manejar la
excepción, en lugar de verificar todo antes (**LBYL**). Por ejemplo, abrir un archivo y capturar
`FileNotFoundError` evita la condición de carrera de verificar que existe y que lo borren justo después.

<Callout type="warning" title="Nunca un except desnudo">
  `except:` sin tipo captura también `KeyboardInterrupt` y `SystemExit`. Capturá excepciones específicas, y
  usá `except Exception` sólo en el borde de la aplicación, registrando el error.
</Callout>

## Context managers

`with` garantiza que un recurso se libere al salir del bloque, aunque haya una excepción:

```python
with open("orders.csv", encoding="utf-8") as file:
    rows = file.readlines()
# el archivo ya está cerrado

from contextlib import contextmanager

@contextmanager
def transaction(connection):
    try:
        yield connection
        connection.commit()
    except Exception:
        connection.rollback()
        raise

with transaction(conn) as tx:
    tx.execute("UPDATE stock SET quantity = quantity - 1 WHERE sku = %s", (sku,))
```

## Módulos, paquetes y pyproject.toml

Un **módulo** es un archivo `.py`; un **paquete** es una carpeta de módulos. Un proyecto moderno se describe en
`pyproject.toml`:

```text
shop/
├── pyproject.toml
├── uv.lock                 # versiones exactas de todo el árbol de dependencias
├── src/shop/
│   ├── __init__.py
│   ├── orders/
│   │   ├── domain.py
│   │   └── service.py
│   └── main.py
└── tests/
    └── test_orders.py
```

```toml
[project]
name = "shop"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["fastapi>=0.115", "sqlalchemy>=2.0"]

[dependency-groups]
dev = ["pytest", "mypy", "ruff"]
```

```python
from shop.orders.service import OrderService        # import absoluto desde el paquete

if __name__ == "__main__":                           # sólo se ejecuta al correr el archivo directamente
    main()
```

Herramientas habituales: **uv** o **Poetry** para dependencias y lockfile, **ruff** para lint y formato, **mypy**
para tipos y **pytest** para tests. El lockfile se commitea para que todos los entornos instalen lo mismo.

## Logging

`print` no tiene niveles, contexto ni destino configurable. En aplicaciones se usa `logging`:

```python
import logging

logger = logging.getLogger(__name__)          # un logger por módulo

logger.info("Pedido creado", extra={"order_id": order.id})
logger.warning("Reintento %d de pago", attempt)  # formato perezoso: no arma el string si el nivel está apagado
try:
    process(order)
except PaymentError:
    logger.exception("Falló el cobro")         # incluye el stack trace
```

La configuración (nivel, formato JSON para producción, destino) se hace una vez al arrancar la aplicación.
