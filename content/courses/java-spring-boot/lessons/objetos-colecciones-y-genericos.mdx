## Clases, interfaces y herencia

Una **interfaz** define un contrato; una **clase** lo implementa. Java permite heredar de una sola clase
(`extends`) e implementar varias interfaces (`implements`). Desde Java 8 las interfaces pueden tener métodos
`default` con implementación.

```java
public interface PaymentMethod {
    PaymentResult charge(long amountCents);

    default boolean supportsRefunds() {
        return true;
    }
}

public class CardPayment implements PaymentMethod {
    private final String token;

    public CardPayment(String token) {
        this.token = token;
    }

    @Override
    public PaymentResult charge(long amountCents) {
        // llamaría al proveedor de pagos
        return PaymentResult.approved("tx-" + token);
    }
}
```

`@Override` hace que el compilador verifique que realmente estás sobrescribiendo un método. Una clase `abstract`
puede tener métodos sin implementar y no se instancia.

<Callout type="tip" title="Composición antes que herencia">
  La herencia acopla la subclase a los detalles de la clase padre. Para reutilizar comportamiento, en general
  es mejor que un objeto **tenga** otro (composición) y dependa de una interfaz. Es lo que hace posible la
  inyección de dependencias de Spring.
</Callout>

## Records, enums y sealed

Un **record** (Java 16) es una clase inmutable para datos: el compilador genera el constructor, los accessors,
`equals`, `hashCode` y `toString`.

```java
public record Money(long cents, String currency) {
    public Money {                          // constructor compacto: validación
        if (cents < 0) throw new IllegalArgumentException("Monto negativo");
        if (currency == null || currency.length() != 3) throw new IllegalArgumentException("Moneda inválida");
    }

    public Money plus(Money other) {
        if (!currency.equals(other.currency)) throw new IllegalArgumentException("Monedas distintas");
        return new Money(cents + other.cents, currency);
    }
}

var price = new Money(1500, "ARS");
price.cents();   // los accessors no llevan "get"
```

Un **enum** modela un conjunto cerrado de valores y puede tener campos y métodos:

```java
public enum ShipmentStatus {
    CREATED, PICKED_UP, IN_TRANSIT, DELIVERED, CANCELLED;

    public boolean isFinal() {
        return this == DELIVERED || this == CANCELLED;
    }
}
```

Con **sealed** (Java 17) se declara qué tipos pueden implementar una interfaz. Combinado con records y el pattern
matching de `switch` (Java 21), el compilador verifica que se cubran todos los casos:

```java
public sealed interface PaymentEvent permits Approved, Rejected, Refunded {}
public record Approved(String txId, long cents) implements PaymentEvent {}
public record Rejected(String reason) implements PaymentEvent {}
public record Refunded(String txId) implements PaymentEvent {}

String describe(PaymentEvent event) {
    return switch (event) {                  // sin default: si falta un caso, no compila
        case Approved a -> "Aprobado por " + a.cents();
        case Rejected r -> "Rechazado: " + r.reason();
        case Refunded f -> "Reembolsado " + f.txId();
    };
}
```

## equals y hashCode

Por defecto, `equals` compara **identidad** (si son el mismo objeto). Para objetos de valor hay que sobrescribirlo,
y **siempre junto con `hashCode`**:

- Si `a.equals(b)`, entonces `a.hashCode() == b.hashCode()`.
- Lo inverso no es necesario: dos objetos distintos pueden compartir hash.

Si se rompe el contrato, un `HashSet` puede guardar duplicados o un `HashMap` no encontrar la clave. Los records ya lo
implementan bien; en clases comunes se usa `Objects.equals` y `Objects.hash`, o lo genera el IDE.

```java
@Override
public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof TrackingCode other)) return false;   // pattern matching de instanceof (Java 16)
    return code.equals(other.code);
}

@Override
public int hashCode() {
    return Objects.hash(code);
}
```

## El Collections Framework

| Interfaz        | Implementación habitual | Acceso                     | Notas                                               |
| --------------- | ----------------------- | -------------------------- | --------------------------------------------------- |
| `List`          | `ArrayList`             | índice O(1), búsqueda O(n) | Orden de inserción, permite duplicados              |
| `Set`           | `HashSet`               | contiene O(1) promedio     | Sin duplicados (usa equals/hashCode)                |
| `Set` ordenado  | `TreeSet`               | O(log n)                   | Ordenado por comparador                             |
| `Map`           | `HashMap`               | get/put O(1) promedio      | Sin orden garantizado                               |
| `Map`           | `LinkedHashMap`         | O(1)                       | Mantiene orden de inserción (base de una caché LRU) |
| `Map` ordenado  | `TreeMap`               | O(log n)                   | Rangos: `headMap`, `ceilingKey`                     |
| `Queue`/`Deque` | `ArrayDeque`            | O(1) en extremos           | Pila y cola; preferible a `Stack`                   |
| Prioridad       | `PriorityQueue`         | O(log n)                   | Heap binario                                        |

```java
List<String> trackingCodes = new ArrayList<>();
trackingCodes.add("TRK-1");

Map<String, Integer> deliveriesByZone = new HashMap<>();
deliveriesByZone.merge("norte", 5, Integer::sum);     // suma si ya existe
deliveriesByZone.getOrDefault("oeste", 0);
deliveriesByZone.computeIfAbsent("sur", k -> 0);

List<String> fixed = List.of("a", "b");            // inmutable: add lanza UnsupportedOperationException
Map<String, Integer> prices = Map.of("A", 100, "B", 200);
```

**HashMap por dentro**: un array de buckets; el índice sale del `hashCode` de la clave. Las colisiones se
encadenan en el bucket y, desde Java 8, un bucket con muchas entradas se convierte en un árbol balanceado. Al superar
el factor de carga (0,75 por defecto) el array se duplica. **No es thread-safe**: para concurrencia, `ConcurrentHashMap`.

## Genéricos

Los genéricos parametrizan tipos para detectar errores en compilación: `List<String>` no acepta un `Integer`.

```java
public class Page<T> {
    private final List<T> items;
    private final String nextCursor;
    // ...
}

public static <T extends Comparable<T>> T max(List<T> values) { /* ... */ }
```

Igual que en TypeScript, los genéricos de Java usan **type erasure**: en runtime `List<String>` y `List<Integer>`
son la misma clase. Por eso no se puede hacer `new T()` ni preguntar `instanceof List<String>`.

Los **comodines** controlan la variancia, con la regla **PECS** (_Producer Extends, Consumer Super_):

```java
// Lee números de cualquier lista de subtipos de Number: la lista "produce"
double sum(List<? extends Number> values) { /* ... */ }

// Agrega enteros a una lista de Integer, Number u Object: la lista "consume"
void fill(List<? super Integer> target) { target.add(42); }
```

## Optional

`Optional<T>` representa un valor de retorno que **puede no existir**, y obliga a quien llama a considerarlo:

```java
Optional<Customer> customer = repository.findByEmail(email);
String name = customer.map(Customer::name).orElse("Invitado");
Customer found = customer.orElseThrow(() -> new CustomerNotFound(email));
```

Usalo como tipo de retorno. No conviene en campos, parámetros ni colecciones (`Optional<List<…>>`: devolvé una lista
vacía). Nunca llames `get()` sin verificar: para eso está `orElseThrow`.

## Resumen

Modelá con interfaces y composición, records para datos inmutables, enums y sealed para conjuntos cerrados.
Respetá equals/hashCode, elegí la colección por su complejidad, usá genéricos con PECS y Optional sólo como retorno.
