## Qué son Spring y Spring Boot

**Spring Framework** es el framework más usado del ecosistema Java para aplicaciones empresariales. Su núcleo es un
**contenedor de inversión de control (IoC)**: en lugar de que cada objeto cree sus dependencias con `new`, el
contenedor crea los objetos (llamados **beans**), resuelve qué necesita cada uno y se los inyecta.

**Spring Boot** se apoya en Spring y resuelve la parte tediosa:

- **Auto-configuración**: configura beans según las librerías que hay en el classpath.
- **Starters**: dependencias agrupadas (`spring-boot-starter-web`, `spring-boot-starter-data-jpa`…).
- **Servidor embebido**: la aplicación es un `.jar` ejecutable con Tomcat adentro.
- **Actuator**: health checks, métricas e información operativa.

Spring Boot 4 (sobre Spring Framework 7) requiere **Java 17 o superior**. El punto de partida habitual es
[Spring Initializr](https://start.spring.io/), que genera el proyecto con Maven o Gradle.

```java
@SpringBootApplication           // configuración + escaneo de componentes + auto-configuración
public class ShopApplication {
    public static void main(String[] args) {
        SpringApplication.run(ShopApplication.class, args);
    }
}
```

## Beans e inyección de dependencias

Las anotaciones de estereotipo marcan clases como beans: `@Component` (genérica), `@Service` (lógica de negocio),
`@Repository` (acceso a datos, traduce excepciones de persistencia) y `@Controller`/`@RestController` (web).

```java
@Service
public class EnrollmentService {
    private final CourseCatalog courses;
    private final PaymentGateway payments;
    private final EnrollmentRepository enrollments;

    // Con un único constructor, Spring lo usa para inyectar: no hace falta @Autowired
    public EnrollmentService(CourseCatalog courses, PaymentGateway payments, EnrollmentRepository enrollments) {
        this.courses = courses;
        this.payments = payments;
        this.enrollments = enrollments;
    }

    public Enrollment enroll(EnrollCommand command) { /* ... */ }
}
```

**Inyectá por constructor**: las dependencias quedan explícitas, los campos pueden ser `final` y en un test unitario
creás el servicio con `new` y fakes, sin levantar Spring.

Para objetos que no son tuyos (un cliente HTTP, un SDK) se declara un método `@Bean` en una clase `@Configuration`:

```java
@Configuration
public class HttpClientsConfig {
    @Bean
    RestClient paymentsClient(PaymentsProperties props) {
        return RestClient.builder().baseUrl(props.baseUrl()).build();
    }
}
```

<Callout type="warning" title="Los beans son singleton y compartidos entre hilos">
  Por defecto hay una sola instancia de cada bean para toda la aplicación, y la usan todas las requests al
  mismo tiempo. Nunca guardes datos de una request (el usuario actual, la inscripción que se está procesando)
  en un campo de un `@Service`.
</Callout>

```java
public record CreateCourseRequest(
    @NotBlank String title,
    @Positive int capacity,
    @NotBlank @Size(min = 2, max = 2) String language) {}

public record CourseResponse(String id, String title, int capacity, String language) {}

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService courses;

    public CourseController(CourseService courses) {
        this.courses = courses;
    }

    @GetMapping("/{id}")
    public CourseResponse get(@PathVariable String id) {
        return courses.get(id);                                    // se serializa a JSON con Jackson
    }

    @PostMapping
    public ResponseEntity<CourseResponse> create(@Valid @RequestBody CreateCourseRequest request) {
        CourseResponse created = courses.create(request);
        return ResponseEntity.created(URI.create("/api/courses/" + created.id())).body(created);
    }
}
```

- Los **DTOs** (records) definen el contrato de la API: no expongas entidades JPA directamente.
- `@Valid` dispara Bean Validation (`spring-boot-starter-validation`); si falla, Spring responde 400.
- `@PathVariable`, `@RequestParam` y `@RequestBody` mapean las partes de la request.

### Manejo de errores centralizado

```java
@RestControllerAdvice
public class ApiErrors {
    @ExceptionHandler(CourseNotFoundException.class)
    ProblemDetail notFound(CourseNotFoundException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, e.getMessage());
    }

    @ExceptionHandler(CourseFullException.class)
    ProblemDetail conflict(CourseFullException e) {
        return ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, e.getMessage());
    }
}
```

`ProblemDetail` produce respuestas con el formato estándar de errores HTTP (RFC 9457): `type`, `title`, `status` y
`detail`.

## Configuración y perfiles

```yaml
# application.yml
payments:
  base-url: https://api.payments.example
  timeout: 3s
spring:
  datasource:
    url: ${DATABASE_URL}
---
spring.config.activate.on-profile: dev
payments.base-url: http://localhost:8089
```

```java
@ConfigurationProperties(prefix = "payments")
public record PaymentsProperties(String baseUrl, Duration timeout) {}
// Se registra con @EnableConfigurationProperties o @ConfigurationPropertiesScan
```

Las propiedades tipadas se validan al arrancar y se inyectan como cualquier bean. Los **perfiles** (`dev`, `test`,
`prod`) activan configuración distinta por entorno con `SPRING_PROFILES_ACTIVE`; los secretos van en variables de
entorno, nunca en el repositorio.

## Cómo organizar el código

La estructura clásica es por capas (controller → service → repository), pero en aplicaciones medianas suele ser más
mantenible **por funcionalidad** (`enrollments`, `payments`, `courses`), cada paquete con sus capas internas y una API
pública mínima. Es la idea del monolito modular, que Spring Modulith ayuda a verificar. La arquitectura hexagonal
encaja naturalmente: el dominio define interfaces (puertos) y Spring inyecta los adaptadores.

## Resumen

Spring crea y conecta los beans; Spring Boot los configura automáticamente y empaqueta la aplicación con su servidor.
Con inyección por constructor, DTOs validados, un manejador central de errores y configuración por perfiles tenés la
base de cualquier API empresarial en Java.
