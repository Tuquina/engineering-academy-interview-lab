## Qué vas a aprender en este curso

React es la librería con la que se construye el frontend de este stack (y de esta misma plataforma). Si venís de
backend, el cambio más grande no es la sintaxis: es el **modelo mental**. Este curso lo construye en orden:

| Módulo                      | Qué vas a poder hacer                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------- |
| Introducción                | Escribir componentes con props, estado, eventos y listas.                                 |
| Componentes y renderizado   | Predecir cuándo y por qué se renderiza un componente; componer en lugar de heredar.       |
| Hooks                       | Usar estado, efectos, memoización, refs, contexto y custom hooks sin los errores típicos. |
| Estado, datos y formularios | Separar server state de client state, cargar datos, manejar formularios y errores.        |
| Calidad y arquitectura      | Optimizar con mediciones, testear, hacer interfaces accesibles y seguras.                 |

## Qué es React y qué problema resuelve

Una interfaz web es un árbol de elementos (el **DOM**) que el navegador dibuja. La forma "clásica" de hacerla
interactiva era **imperativa**: escuchar un evento y modificar el DOM paso a paso.

```js
// Imperativo: hay que recordar actualizar cada lugar que depende del dato
button.addEventListener("click", () => {
  paidCount++;
  counter.textContent = String(paidCount);
  if (paidCount > 0) emptyMessage.remove();
  list.appendChild(createRow(lastPayment));
});
```

Con pocos datos funciona. Con muchos, es fácil olvidar un lugar y que la pantalla muestre algo que no coincide con
los datos. **React es declarativo**: describís **cómo se ve la interfaz para un estado dado**, y React se encarga de
actualizar el DOM cuando el estado cambia.

```tsx
function PaymentsPanel({ payments }: { payments: Payment[] }) {
  return (
    <section>
      <h2>Pagos recibidos: {payments.length}</h2>
      {payments.length === 0 ? <p>Todavía no hay pagos.</p> : <PaymentList payments={payments} />}
    </section>
  );
}
```

Si venís de .NET, la idea se parece a Blazor o a los bindings de WPF: el código describe la vista a partir del
modelo. La diferencia es que en React **la vista se recalcula completa** (en memoria) en cada cambio, y React
decide qué tocar en el DOM real. Eso se ve en detalle en la lección de renderizado.

## Componentes y JSX

Un **componente** es una función de JavaScript que devuelve la descripción de una parte de la interfaz. Su nombre
**empieza con mayúscula** (así JSX lo distingue de una etiqueta HTML).

```tsx
export function DebtCard() {
  return (
    <article className="debt-card">
      <h3>Deuda #1042</h3>
      <p>Saldo: $ 15.000</p>
    </article>
  );
}
```

**JSX** es una extensión de sintaxis que parece HTML pero se compila a llamadas de funciones de JavaScript. Las
reglas que más sorprenden:

| Regla                                  | Ejemplo                                                                       |
| -------------------------------------- | ----------------------------------------------------------------------------- |
| Un solo elemento raíz (o un fragmento) | `<>...</>` agrupa sin agregar un nodo al DOM                                  |
| `className` en lugar de `class`        | `<p className="muted">`                                                       |
| Atributos en camelCase                 | `onClick`, `tabIndex`, `aria-label` (los `aria-*` y `data-*` van con guiones) |
| Todas las etiquetas se cierran         | `<img />`, `<input />`, `<br />`                                              |
| `{}` inserta expresiones de JavaScript | `<p>{formatAmount(debt.balanceCents)}</p>`                                    |
| `style` recibe un objeto               | `<div style={{ marginTop: 8 }}>`                                              |

Dentro de `{}` va **cualquier expresión** (una variable, una llamada, un ternario), pero no sentencias como `if` o
`for`. Por eso las condiciones y los bucles se escriben con expresiones, como se ve más abajo.

```tsx
// Lo que el compilador genera a partir del JSX (simplificado):
<p className="muted">{name}</p>
// → jsx("p", { className: "muted", children: name })
```

## Props: los parámetros de un componente

Las **props** son los datos que un componente recibe de su padre. En TypeScript se tipan como un objeto:

```tsx
interface DebtCardProps {
  id: string;
  customerName: string;
  balanceCents: number;
  status: "pending" | "promised" | "paid";
}

export function DebtCard({ id, customerName, balanceCents, status }: DebtCardProps) {
  return (
    <article>
      <h3>
        {customerName} · #{id}
      </h3>
      <p>Saldo: {formatAmount(balanceCents)}</p>
      <StatusBadge status={status} />
    </article>
  );
}

// Uso: los atributos JSX son las props
<DebtCard id="1042" customerName="Ana Pérez" balanceCents={1_500_000} status="pending" />;
```

- Las props son **de sólo lectura**: un componente nunca modifica las props que recibe.
- Los strings van entre comillas; cualquier otro valor, entre llaves (`balanceCents={1500000}`).
- **`children`** es una prop especial: lo que va entre la etiqueta de apertura y la de cierre.

```tsx
function Card({ title, children }: { title: string; children: React.ReactNode }) {
  return (
    <section className="card">
      <h2>{title}</h2>
      {children}
    </section>
  );
}

<Card title="Promesas de pago">
  <PromiseList />
</Card>;
```

## Estado con useState

Las props vienen de afuera. El **estado** es la memoria propia de un componente: datos que cambian con la
interacción. Se declara con el hook `useState`:

```tsx
import { useState } from "react";

export function ReminderToggle() {
  const [enabled, setEnabled] = useState(false); // valor inicial

  return (
    <button type="button" aria-pressed={enabled} onClick={() => setEnabled(!enabled)}>
      Recordatorios: {enabled ? "activados" : "desactivados"}
    </button>
  );
}
```

`useState` devuelve un par: el **valor actual** y una **función para cambiarlo**. Llamar al setter le pide a React
que **vuelva a ejecutar el componente** (un nuevo _render_) con el valor nuevo. Es fundamental entender que:

- Modificar una variable común no actualiza la pantalla: sólo el setter dispara un render.
- El estado se reemplaza, no se muta: para objetos y arrays se crea uno nuevo (`setItems([...items, item])`).
- Cada instancia del componente tiene su propio estado.

<Callout type="info" title="¿Qué es un hook?">
  Los hooks son funciones que empiezan con `use` y le dan capacidades a un componente: estado (`useState`),
  efectos (`useEffect`), contexto (`useContext`), entre otras. Tienen dos reglas: se llaman siempre en el
  nivel superior del componente (nunca dentro de un `if` o un bucle) y sólo desde componentes o desde otros
  hooks.
</Callout>

## Eventos

Los eventos se manejan con props `on...` que reciben **una función**:

```tsx
function PromiseForm({ onSubmit }: { onSubmit: (date: string) => void }) {
  const [date, setDate] = useState("");

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault(); // evita la recarga de la página
        onSubmit(date);
      }}
    >
      <label htmlFor="promised-for">Fecha de pago</label>
      <input id="promised-for" type="date" value={date} onChange={(event) => setDate(event.target.value)} />
      <button type="submit">Registrar promesa</button>
    </form>
  );
}
```

Un error clásico: `onClick={handleClick()}` **llama** a la función durante el render; lo correcto es pasarla:
`onClick={handleClick}` o `onClick={() => handleClick(id)}`.

Observá también el patrón de **comunicación hacia arriba**: el formulario no sabe qué hacer con la fecha; recibe
una función `onSubmit` de su padre y la llama. **Los datos bajan por props; los cambios suben por callbacks.**

## Renderizado condicional

```tsx
function DebtStatus({ debt }: { debt: Debt }) {
  if (debt.status === "paid") return <p>Pagada ✓</p>; // retorno temprano

  return (
    <div>
      {debt.status === "promised" ? <p>Promesa para el {debt.promisedFor}</p> : <p>Pendiente</p>}
      {debt.overdueDays > 30 && <OverdueWarning days={debt.overdueDays} />}
    </div>
  );
}
```

<Callout type="warning" title="La trampa del 0 con &&">
  `{items.length && <List />}` muestra un `0` en pantalla cuando la lista está vacía, porque `0` es un valor
  que React sí renderiza. Escribí `{items.length > 0 && <List />}`.
</Callout>

## Listas y keys

Para mostrar una colección se transforma el array en elementos con `map`. Cada elemento necesita una **key**:

```tsx
function DebtList({ debts }: { debts: Debt[] }) {
  return (
    <ul>
      {debts.map((debt) => (
        <li key={debt.id}>
          <DebtCard {...debt} />
        </li>
      ))}
    </ul>
  );
}
```

La key le permite a React **reconocer cada elemento entre renders**: saber que la fila con `id="1042"` es la misma
aunque haya cambiado de posición. Debe ser **estable y única entre hermanos**, normalmente el ID del dato. Usar el
índice del array como key causa bugs cuando la lista se reordena o se filtra: el estado de una fila (un input, un
checkbox) queda asociado a la fila equivocada.

## Estructura de archivos y estilos

No hay una estructura obligatoria. Una convención habitual: un componente por archivo, nombrado igual que el
componente, agrupado **por funcionalidad** (`features/debts/debt-card.tsx`) más que por tipo. Para estilos, las
opciones más comunes son CSS Modules, Tailwind CSS (la que usa esta plataforma) y librerías de componentes con
estilos propios.

## Comparación con C# y Java

| Concepto            | Blazor / WPF (.NET)               | JavaFX / Vaadin (Java)    | React                                         |
| ------------------- | --------------------------------- | ------------------------- | --------------------------------------------- |
| Unidad de UI        | Componente `.razor` / UserControl | Node / Component          | Función que devuelve JSX                      |
| Plantilla           | Razor / XAML                      | FXML / código Java        | JSX (JavaScript con sintaxis de marcado)      |
| Parámetros          | `[Parameter]`                     | Propiedades / constructor | Props (sólo lectura)                          |
| Estado              | Campos + `StateHasChanged()`      | Properties observables    | `useState`: el setter dispara un nuevo render |
| Actualizar la vista | Diff del árbol de render (Blazor) | Bindings                  | Re-render + reconciliación                    |
| Eventos             | `@onclick`                        | `setOnAction`             | `onClick={fn}`                                |

## Errores frecuentes

- **Mutar el estado** (`items.push(x); setItems(items)`): React compara por referencia y puede no re-renderizar.
- **Llamar al handler en lugar de pasarlo**: `onClick={save()}`.
- **Usar el índice como key** en listas que cambian.
- **Llamar hooks dentro de condiciones o bucles.**
- **Nombres de componentes en minúscula**: JSX los interpreta como etiquetas HTML.
- **`{count && ...}` con números**: muestra `0`.
- **Esperar que una variable común "recuerde" su valor** entre renders: cada render es una nueva ejecución de la
  función.
