## Slices por dentro

Un **array** en Go tiene tamaño fijo y es parte del tipo (`[3]int`). Lo que se usa casi siempre es el **slice**: un
descriptor con tres campos.

```go
s := make([]int, 0, 4)     // len 0, cap 4
s = append(s, 1, 2, 3)     // entra en la capacidad: mismo array
s = append(s, 4, 5)        // se supera cap: se reserva un array más grande y se copian los datos
len(s), cap(s)             // 5 y una capacidad mayor (el crecimiento es un detalle de implementación)
```

`append` **puede devolver un slice que apunta a otro array**, por eso siempre se asigna su resultado.

### Aliasing: el error clásico

```go
all := []string{"a", "b", "c", "d"}
firstTwo := all[:2]                  // comparte el array con all
firstTwo = append(firstTwo, "X")     // ¡hay capacidad! escribe sobre all[2]
fmt.Println(all)                     // [a b X d]

independent := slices.Clone(all[:2]) // copia propia (o copy en un slice nuevo)
```

Si una función recibe un slice y lo modifica o hace `append`, puede afectar al llamador. Cuando necesitás
independencia, copiá. Y si sabés cuántos elementos vas a agregar, pre-asigná con `make([]T, 0, n)` para evitar
realocaciones.

## Maps

```go
counts := make(map[string]int)
counts["SKU-1"]++                         // el zero value permite incrementar sin inicializar

var byCustomer map[string][]Order         // map nil: se puede leer, pero escribir produce panic
byCustomer = map[string][]Order{}

keys := slices.Sorted(maps.Keys(counts))  // el orden de iteración no está definido: ordenar si importa
```

<Callout type="danger" title="Los maps no son seguros para escrituras concurrentes">
  Escribir en un map desde varias goroutines sin sincronización es un error: el runtime puede abortar el
  programa con un *fatal error* de acceso concurrente. Protegelo con `sync.Mutex` o `sync.RWMutex`, o usá
  `sync.Map` en los casos para los que está pensado (muchas lecturas, claves estables).
</Callout>

## Strings y bytes

Un `string` es una secuencia **inmutable de bytes** (normalmente UTF-8). `len` cuenta bytes, `range` recorre `rune`
(code points) y `[]byte(s)` copia. Para construir strings en bucles se usa `strings.Builder`; el paquete `strings` trae
`Split`, `Contains`, `TrimSpace`, `EqualFold` y más.

## Paquetes y módulos

Cada carpeta es un **paquete**. Lo que empieza con mayúscula se exporta; lo demás es privado del paquete. Una
estructura habitual para un servicio:

```text
shop/
├── go.mod
├── cmd/
│   └── api/main.go            # punto de entrada: arma dependencias y arranca el servidor
└── internal/                  # no puede importarse desde otros módulos
    ├── orders/
    │   ├── order.go           # dominio
    │   ├── service.go
    │   └── postgres.go        # adaptador
    └── httpapi/
        └── handlers.go
```

- **Un paquete por responsabilidad**, con nombres cortos en minúscula (`orders`, no `orderService`).
- `internal/` es una regla del compilador: sólo el código del mismo módulo puede importarlo.
- Evitá paquetes genéricos como `utils` o `common`: esconden dependencias.
- No hay dependencias circulares entre paquetes: el compilador las rechaza.

## Testing

El testing viene en la librería estándar. Los tests van en archivos `_test.go` junto al código:

```go
// discount_test.go
func TestApplyDiscount(t *testing.T) {
    tests := []struct {
        name     string
        cents    int64
        pct      int
        want     int64
        wantErr  bool
    }{
        {name: "sin descuento", cents: 1000, pct: 0, want: 1000},
        {name: "10 por ciento", cents: 1000, pct: 10, want: 900},
        {name: "porcentaje inválido", cents: 1000, pct: 120, wantErr: true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            got, err := ApplyDiscount(tt.cents, tt.pct)
            if (err != nil) != tt.wantErr {
                t.Fatalf("error = %v, wantErr %v", err, tt.wantErr)
            }
            if got != tt.want {
                t.Errorf("ApplyDiscount(%d, %d) = %d, want %d", tt.cents, tt.pct, got, tt.want)
            }
        })
    }
}

func BenchmarkApplyDiscount(b *testing.B) {
    for b.Loop() {                // Go 1.24+; antes: for i := 0; i < b.N; i++
        ApplyDiscount(1000, 10)
    }
}
```

```bash
go test ./...                     # todos los tests
go test -run TestApplyDiscount/10 # un caso concreto
go test -race ./...               # detector de data races
go test -bench . -benchmem        # benchmarks con asignaciones de memoria
go test -cover ./...              # cobertura
```

Los **tests de tabla** son el estilo idiomático: agregar un caso es agregar una fila. También hay **fuzzing**
integrado (`func FuzzX(f *testing.F)`) para generar entradas automáticamente, y `net/http/httptest` para probar
handlers sin levantar un servidor real.

## Resumen

Entender slices (puntero, len y cap) evita los errores más sutiles de Go; los maps necesitan sincronización bajo
concurrencia. Los paquetes chicos con internal/ mantienen la arquitectura limpia, y el testing de la librería estándar
(tablas, race detector, benchmarks y fuzzing) alcanza para un proyecto profesional.
