## Una API con la librería estándar

Desde **Go 1.22**, el `ServeMux` de la librería estándar enruta por **método** y admite **parámetros de ruta**, así
que muchos servicios no necesitan un framework:

```go
func main() {
    store := NewOrderStore(db)
    mux := http.NewServeMux()

    mux.HandleFunc("GET /orders/{id}", func(w http.ResponseWriter, r *http.Request) {
        order, err := store.Find(r.Context(), r.PathValue("id"))
        if errors.Is(err, ErrNotFound) {
            writeError(w, http.StatusNotFound, "pedido inexistente")
            return
        }
        if err != nil {
            writeError(w, http.StatusInternalServerError, "error interno")
            return
        }
        writeJSON(w, http.StatusOK, order)
    })

    mux.HandleFunc("POST /orders", createOrder(store))
    // ...
}
```

Alternativas populares: **chi** (compatible con net/http, sólo agrega un router y middlewares), **Gin** y **Echo**
(con su propio contexto y helpers).

## JSON

```go
type CreateOrderRequest struct {
    CustomerID string `json:"customerId"`
    Items      []struct {
        SKU      string `json:"sku"`
        Quantity int    `json:"quantity"`
    } `json:"items"`
}

func createOrder(store *OrderStore) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        r.Body = http.MaxBytesReader(w, r.Body, 1<<20)        // máximo 1 MB
        decoder := json.NewDecoder(r.Body)
        decoder.DisallowUnknownFields()

        var req CreateOrderRequest
        if err := decoder.Decode(&req); err != nil {
            writeError(w, http.StatusBadRequest, "JSON inválido")
            return
        }
        if req.CustomerID == "" || len(req.Items) == 0 {
            writeError(w, http.StatusUnprocessableEntity, "faltan datos del pedido")
            return
        }
        order, err := store.Create(r.Context(), req)
        if err != nil {
            writeError(w, http.StatusInternalServerError, "error interno")
            return
        }
        writeJSON(w, http.StatusCreated, order)
    }
}

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}
```

Los **struct tags** (`json:"customerId"`) controlan los nombres en JSON; sólo se serializan los campos exportados
(con mayúscula). Para validaciones más ricas se usan librerías como go-playground/validator.

## Middleware

Un middleware recibe un `http.Handler` y devuelve otro que lo envuelve:

```go
func logging(logger *slog.Logger) func(http.Handler) http.Handler {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            start := time.Now()
            next.ServeHTTP(w, r)
            logger.Info("request", "method", r.Method, "path", r.URL.Path, "duration", time.Since(start))
        })
    }
}

handler := logging(logger)(auth(mux))     // de afuera hacia adentro
```

`net/http` ya recupera los panics de cada request para que el servidor no se caiga, pero conviene un middleware propio
que registre el error y responda 500 con un formato consistente.

## Acceso a datos

`database/sql` define una interfaz común y **administra un pool de conexiones**; el driver concreto (por ejemplo,
**pgx** para PostgreSQL) se registra aparte. pgx también puede usarse directamente con su propia API.

```go
func (s *OrderStore) Find(ctx context.Context, id string) (Order, error) {
    var o Order
    err := s.db.QueryRowContext(ctx,
        `SELECT id, customer_id, status, total_cents FROM orders WHERE id = $1`, id,   // parámetros: nunca concatenar
    ).Scan(&o.ID, &o.CustomerID, &o.Status, &o.TotalCents)
    if errors.Is(err, sql.ErrNoRows) {
        return Order{}, ErrNotFound
    }
    return o, err
}

func (s *OrderStore) Pay(ctx context.Context, id string) error {
    tx, err := s.db.BeginTx(ctx, nil)
    if err != nil {
        return err
    }
    defer tx.Rollback()                 // no hace nada si ya se hizo Commit

    res, err := tx.ExecContext(ctx, `UPDATE orders SET status = 'PAID' WHERE id = $1 AND status = 'CREATED'`, id)
    if err != nil {
        return err
    }
    if n, _ := res.RowsAffected(); n == 0 {
        return ErrInvalidState
    }
    return tx.Commit()
}
```

- Pasá siempre `ctx`: las consultas se cancelan si la request se cancela.
- Con `Query`, cerrá `rows` (`defer rows.Close()`) y revisá `rows.Err()`; si no, se pierden conexiones del pool.
- Configurá el pool: `SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`.
- Herramientas como **sqlc** generan código tipado a partir de SQL; **GORM** es el ORM más conocido.

## Producción

```go
func main() {
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()

    server := &http.Server{
        Addr:              ":8080",
        Handler:           handler,
        ReadHeaderTimeout: 5 * time.Second,     // sin timeouts, un cliente lento retiene conexiones
        WriteTimeout:      15 * time.Second,
        IdleTimeout:       60 * time.Second,
    }

    go func() {
        if err := server.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
            slog.Error("servidor", "error", err)
            os.Exit(1)
        }
    }()

    <-ctx.Done()                                          // llegó SIGTERM
    shutdownCtx, cancel := context.WithTimeout(context.Background(), 20*time.Second)
    defer cancel()
    server.Shutdown(shutdownCtx)                          // espera las requests en curso
    db.Close()
}
```

- **Timeouts**: el `http.Server` y el `http.Client` por defecto **no tienen timeouts**. Configuralos siempre.
- **Logs**: `log/slog` (Go 1.21) da logs estructurados con niveles y salida JSON.
- **Testing**: `httptest.NewRecorder` y `httptest.NewServer` prueban handlers y clientes sin red real.
- **Profiling**: `net/http/pprof` expone perfiles de CPU, memoria y goroutines (en un puerto interno, nunca público).
- **Despliegue**: Go compila a un **binario estático** (con `CGO_ENABLED=0`), así la imagen final puede ser
  `distroless` o incluso `scratch`, de pocos megabytes.

```dockerfile
FROM golang:1.27 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /api ./cmd/api

FROM gcr.io/distroless/static-debian12
COPY --from=build /api /api
USER nonroot
ENTRYPOINT ["/api"]
```

## Resumen

Con net/http, JSON con límites, middlewares, database/sql con contextos y transacciones, timeouts en todos lados y un
apagado ordenado, un servicio Go está listo para producción y se despliega como un binario estático en una imagen
mínima.
