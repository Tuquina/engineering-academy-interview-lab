## Motivación

La plataforma envía mensajes de cobranza por un proveedor de WhatsApp. El negocio sólo necesita "enviar este
mensaje a este deudor y saber si se aceptó". El SDK del proveedor, en cambio, tiene su propio formato de números,
plantillas con parámetros posicionales, códigos de error numéricos y excepciones propias.

## Ejemplo incorrecto

```ts
// En el caso de uso de campañas:
import { WaClient, WaError } from "proveedor-whatsapp-sdk";

const client = new WaClient(process.env.WA_TOKEN!);

export async function contactDebtor(debtor: Debtor) {
  try {
    await client.messages.create({
      to: `whatsapp:+${debtor.phone.replace(/\D/g, "")}`,
      template: { name: "recordatorio_v3", params: [debtor.name, String(debtor.amountCents / 100)] },
    });
  } catch (error) {
    if (error instanceof WaError && error.code === 131047) {
      // Ventana de 24 h cerrada: ¿qué significa para el negocio?
    }
    throw error;
  }
}
```

El caso de uso conoce el formato del número, el nombre de la plantilla del proveedor y sus códigos de error.

## Implementación correcta

```ts
// Contrato definido por la aplicación (puerto):
export type SendResult =
  | { status: "accepted"; messageId: string }
  | { status: "rejected"; reason: "outside-window" | "invalid-number" | "provider-error" };

export interface MessageSender {
  sendReminder(input: { phoneE164: string; debtorName: string; amountCents: number }): Promise<SendResult>;
}

// Adaptador: la única pieza que conoce el SDK.
export class WhatsAppSender implements MessageSender {
  constructor(private readonly client: WaClient) {}

  async sendReminder(input: {
    phoneE164: string;
    debtorName: string;
    amountCents: number;
  }): Promise<SendResult> {
    try {
      const response = await this.client.messages.create({
        to: `whatsapp:${input.phoneE164}`,
        template: {
          name: "recordatorio_v3",
          params: [input.debtorName, (input.amountCents / 100).toFixed(2)],
        },
      });
      return { status: "accepted", messageId: response.sid };
    } catch (error) {
      if (error instanceof WaError && error.code === 131047)
        return { status: "rejected", reason: "outside-window" };
      if (error instanceof WaError && error.code === 21211)
        return { status: "rejected", reason: "invalid-number" };
      return { status: "rejected", reason: "provider-error" };
    }
  }
}
```

El caso de uso recibe un `MessageSender` y trabaja con `SendResult`, un tipo propio que expresa los resultados que
le importan al negocio. En los tests se inyecta un `MessageSender` falso.

## Ejercicio

Se agrega un segundo canal (SMS) con otro proveedor. ¿Qué cambia en el caso de uso? ¿Dónde decidirías qué canal
usar?

<Reveal>

El caso de uso no cambia si sigue dependiendo de `MessageSender`. Se agrega un `SmsSender` que implementa el mismo
contrato. La decisión de canal es una regla de negocio (preferencia del deudor, ventana horaria, costo) y no debe
vivir en ningún adaptador: puede ser una estrategia que elige el `MessageSender` adecuado, o un `MessageSender`
compuesto que intenta WhatsApp y cae a SMS ante `outside-window`.

</Reveal>
