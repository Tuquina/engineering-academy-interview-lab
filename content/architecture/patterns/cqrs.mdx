## Motivación

La bandeja del equipo de soporte muestra miles de tickets ordenados por prioridad, con cliente, tiempo restante de
SLA, último mensaje y agente asignado. Calcularlo en cada carga con JOINs sobre tickets, mensajes, clientes y
asignaciones es lento. Mientras tanto, asignar un ticket requiere validar reglas sobre un solo ticket.

## Ejemplo incorrecto

```ts
// Para la bandeja se cargan agregados completos y se ordena en memoria
export async function getInbox(repo: TicketRepository, tenantId: string) {
  const tickets = await repo.findAllByTenant(tenantId); // miles de agregados con todos sus mensajes
  return tickets
    .map((t) => ({ customer: t.customerName, slaLeft: t.slaRemaining(), priority: t.computePriority() }))
    .sort((a, b) => b.priority - a.priority)
    .slice(0, 50);
}
```

El modelo de escritura se usa para leer: carga todo, calcula en memoria y no escala.

## Implementación correcta

```ts
// Lado de escritura: valida y guarda. Publica un evento vía outbox.
export async function assignTicket(deps: WriteDeps, cmd: AssignTicketCommand): Promise<{ ticketId: string }> {
  return deps.unitOfWork(async (tx) => {
    const ticket = await tx.tickets.findById(cmd.ticketId);
    if (!ticket) throw new DomainError("ticket-not-found");
    ticket.assignTo(cmd.agentId); // falla si ya tiene agente o está cerrado
    await tx.tickets.save(ticket);
    await tx.outbox.add({ type: "TicketAssigned", ticketId: ticket.id, agentId: cmd.agentId });
    return { ticketId: ticket.id };
  });
}

// Proyector: mantiene una fila por ticket en la vista de la bandeja (idempotente por versión).
export async function onTicketAssigned(db: Db, event: TicketAssignedEvent) {
  await db.execute(sql`
    UPDATE support_inbox
    SET assignee_id = ${event.agentId}, version = ${event.version}
    WHERE ticket_id = ${event.ticketId} AND version < ${event.version}`);
}

// Lado de lectura: una consulta simple sobre la vista.
export async function getInbox(db: Db, tenantId: string, page: number) {
  return db.execute(sql`
    SELECT ticket_id, customer_name, sla_due_at, last_message_at, assignee_id
    FROM support_inbox WHERE tenant_id = ${tenantId}
    ORDER BY priority DESC LIMIT 50 OFFSET ${page * 50}`);
}
```

## Ejercicio

Una agente toma un ticket y vuelve a la bandeja: el ticket sigue apareciendo sin asignar durante dos segundos y otra
agente lo toma también. ¿Qué cambiarías?

<Reveal>

Primero, la defensa en el lado de escritura: la regla "un ticket se asigna sólo si no tiene agente" (aplicada en el
agregado y con un `UPDATE ... WHERE assignee_id IS NULL` en la base) rechaza la segunda asignación aunque la vista
esté atrasada. Segundo, la interfaz: tras el comando, actualizar la fila de forma optimista con lo que devolvió el
comando, o marcarla como "actualizando" hasta que la vista alcance la versión. La consistencia eventual se diseña,
no se ignora.

</Reveal>
