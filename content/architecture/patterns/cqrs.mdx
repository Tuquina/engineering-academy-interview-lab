## Motivación

La bandeja de los operadores muestra miles de deudores ordenados por prioridad, con saldo, última gestión, promesa
activa y canal preferido. Calcularlo en cada carga con JOINs sobre deudas, cuotas, gestiones y promesas es lento.
Mientras tanto, registrar una promesa requiere validar reglas sobre una sola deuda.

## Ejemplo incorrecto

```ts
// Para la bandeja se cargan agregados completos y se ordena en memoria
export async function getInbox(repo: DebtRepository, tenantId: string) {
  const debts = await repo.findAllByTenant(tenantId); // miles de agregados con todas sus cuotas
  return debts
    .map((d) => ({ debtor: d.debtorName, balance: d.balance(), priority: d.computePriority() }))
    .sort((a, b) => b.priority - a.priority)
    .slice(0, 50);
}
```

El modelo de escritura se usa para leer: carga todo, calcula en memoria y no escala.

## Implementación correcta

```ts
// Lado de escritura: valida y guarda. Publica un evento vía outbox.
export async function registerPromise(
  deps: WriteDeps,
  cmd: RegisterPromiseCommand,
): Promise<{ promiseId: string }> {
  return deps.unitOfWork(async (tx) => {
    const debt = await tx.debts.findById(cmd.debtId);
    if (!debt) throw new DomainError("debt-not-found");
    const promise = debt.promise(cmd.amountCents, cmd.dueDate);
    await tx.debts.save(debt);
    await tx.outbox.add({ type: "PromiseRegistered", debtId: debt.id, promiseId: promise.id });
    return { promiseId: promise.id };
  });
}

// Proyector: mantiene una fila por deudor en la vista de la bandeja (idempotente por versión).
export async function onPromiseRegistered(db: Db, event: PromiseRegisteredEvent) {
  await db.execute(sql`
    UPDATE debtor_inbox
    SET has_active_promise = true, priority = priority - 500, version = ${event.version}
    WHERE debt_id = ${event.debtId} AND version < ${event.version}`);
}

// Lado de lectura: una consulta simple sobre la vista.
export async function getInbox(db: Db, tenantId: string, page: number) {
  return db.execute(sql`
    SELECT debtor_name, balance_cents, last_contact_at, has_active_promise
    FROM debtor_inbox WHERE tenant_id = ${tenantId}
    ORDER BY priority DESC LIMIT 50 OFFSET ${page * 50}`);
}
```

## Ejercicio

Un operador registra una promesa y vuelve a la bandeja: el deudor sigue apareciendo sin promesa durante dos
segundos y el operador lo registra de nuevo. ¿Qué cambiarías?

<Reveal>

Primero, la defensa en el lado de escritura: la regla "una sola promesa activa" (y un índice único parcial)
rechaza el duplicado aunque la vista esté atrasada. Segundo, la interfaz: tras el comando, actualizar la fila de
forma optimista con lo que devolvió el comando, o marcarla como "actualizando" hasta que la vista alcance la
versión. La consistencia eventual se diseña, no se ignora.

</Reveal>
