## Motivación

Una billetera digital necesita responder "¿por qué mi saldo es este?", reconstruir el saldo de cualquier cuenta a fin
de mes para el regulador y detectar fraudes analizando secuencias de movimientos.

## Ejemplo incorrecto

```ts
async function withdraw(accountId: string, amountCents: number) {
  const account = await db.accounts.find(accountId);
  if (account.balanceCents < amountCents) throw new Error("Saldo insuficiente");
  await db.accounts.update(accountId, { balanceCents: account.balanceCents - amountCents });
  // El saldo anterior se perdió. ¿Cuánto había el 31 de octubre? Imposible saberlo con certeza.
}
```

## Implementación correcta

```ts
type AccountEvent =
  | { type: "AccountOpened"; accountId: string; ownerId: string }
  | { type: "MoneyDeposited"; amountCents: number }
  | { type: "MoneyWithdrawn"; amountCents: number };

interface AccountState {
  balanceCents: number;
  version: number;
}

/** El estado es una función pura de los eventos. */
function evolve(state: AccountState, event: AccountEvent): AccountState {
  switch (event.type) {
    case "AccountOpened":
      return { balanceCents: 0, version: state.version + 1 };
    case "MoneyDeposited":
      return { balanceCents: state.balanceCents + event.amountCents, version: state.version + 1 };
    case "MoneyWithdrawn":
      return { balanceCents: state.balanceCents - event.amountCents, version: state.version + 1 };
  }
}

/** Decidir: valida el comando contra el estado y devuelve los eventos nuevos (o un error). */
function withdraw(state: AccountState, amountCents: number): AccountEvent[] {
  if (amountCents <= 0) throw new Error("Monto inválido");
  if (state.balanceCents < amountCents) throw new Error("Saldo insuficiente");
  return [{ type: "MoneyWithdrawn", amountCents }];
}

async function handleWithdraw(accountId: string, amountCents: number) {
  const events = await eventStore.readStream(`account-${accountId}`);
  const state = events.reduce(evolve, { balanceCents: 0, version: 0 });
  const newEvents = withdraw(state, amountCents);
  // Concurrencia optimista: falla si otro proceso agregó eventos desde que leímos.
  await eventStore.append(`account-${accountId}`, newEvents, { expectedVersion: state.version });
}
```

Las pantallas no reproducen eventos: una **proyección** consume el stream y mantiene una tabla `account_balances`
para consultas rápidas.

## Ejercicio

Un depósito se registró por error con el monto equivocado. ¿Cómo lo corregís si los eventos son inmutables?

<Reveal>

Agregando eventos compensatorios, como en la contabilidad: un `DepositReversed` (o `MoneyWithdrawn` con motivo
"corrección") por el monto erróneo y un `MoneyDeposited` con el correcto, ambos con referencia al evento original y a
quién autorizó la corrección. El historial muestra el error y su corrección; nunca se edita un evento guardado. Las
proyecciones se actualizan solas al procesar los eventos nuevos.

</Reveal>
