## Motivación

Inscribir a un alumno en un curso pago requiere reservar la vacante (servicio de inscripciones), cobrar la matrícula
(servicio de pagos) y enviar la confirmación (servicio de notificaciones). Si el cobro falla, la vacante no debe
quedar ocupada.

## Ejemplo incorrecto

```ts
export async function enrollInCourse(input: EnrollmentInput) {
  const enrollment = await enrollmentsApi.create(input); // servicio 1
  await paymentsApi.charge(enrollment.fee); // servicio 2: si falla, la vacante queda ocupada
  await notificationsApi.sendConfirmation(enrollment.id); // servicio 3
  return enrollment;
}
```

Si el proceso cae después del paso 1, nadie sabe que hay una vacante ocupada sin pagar. Si `charge` falla por timeout, no se
sabe si cobró o no, y reintentarlo puede cobrar dos veces.

## Implementación correcta

```ts
type Step = "reserve-seat" | "charge" | "confirm" | "done" | "compensating" | "failed";

interface EnrollmentSaga {
  id: string;
  step: Step;
  enrollmentId?: string;
  chargeId?: string;
}

export async function advance(saga: EnrollmentSaga, deps: SagaDeps): Promise<EnrollmentSaga> {
  const key = (step: string) => `${saga.id}:${step}`; // idempotencia por saga y paso
  switch (saga.step) {
    case "reserve-seat": {
      const enrollment = await deps.enrollments.createPending(saga.id, key("reserve-seat"));
      return deps.store.save({ ...saga, enrollmentId: enrollment.id, step: "charge" });
    }
    case "charge": {
      const result = await deps.payments.charge(saga.enrollmentId!, key("charge"));
      if (result.status === "declined") return deps.store.save({ ...saga, step: "compensating" });
      await deps.enrollments.activate(saga.enrollmentId!, key("activate"));
      return deps.store.save({ ...saga, chargeId: result.chargeId, step: "confirm" });
    }
    case "confirm": {
      await deps.notifications.enrollmentConfirmed(saga.enrollmentId!, key("confirm")); // no compensable: va al final
      return deps.store.save({ ...saga, step: "done" });
    }
    case "compensating": {
      await deps.enrollments.cancel(saga.enrollmentId!, key("release-seat"));
      return deps.store.save({ ...saga, step: "failed" });
    }
    default:
      return saga;
  }
}
```

Un worker llama a `advance` hasta llegar a `done` o `failed`. Como el estado se persiste después de cada paso y
cada llamada es idempotente, se puede reintentar tras una caída sin repetir efectos.

## Ejercicio

El cobro responde con timeout: no sabés si se cobró. ¿Qué hace la saga?

<Reveal>

No compensa a ciegas ni cobra de nuevo con otra clave. Reintenta `charge` con **la misma clave de idempotencia**:
si el cobro se había hecho, el servicio de pagos devuelve el resultado original; si no, lo ejecuta. Si el servicio
sigue sin responder, la saga queda en `charge` con reintentos con backoff y, pasado un límite, pasa a revisión
manual con alerta. Nunca se asume el resultado de una operación que terminó con timeout.

</Reveal>
