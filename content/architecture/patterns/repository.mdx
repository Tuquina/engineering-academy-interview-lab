## Motivación

El caso de uso "registrar promesa de pago" necesita cargar la deuda con sus promesas activas, aplicar la regla "no
más de una promesa activa y el monto no puede superar el saldo" y guardar. La regla es lo importante; cómo se
guarda es un detalle.

## Ejemplo incorrecto

```ts
export async function registerPromise(db: Db, debtId: string, amountCents: number, dueDate: string) {
  const rows = await db.execute(sql`
    SELECT d.balance_cents, p.id AS promise_id
    FROM debts d LEFT JOIN promises p ON p.debt_id = d.id AND p.status = 'active'
    WHERE d.id = ${debtId}`);
  if (rows.length === 0) throw new Error("no existe");
  if (rows.some((r) => r.promise_id !== null)) throw new Error("ya hay promesa");
  if (amountCents > Number(rows[0].balance_cents)) throw new Error("monto inválido");
  await db.execute(sql`INSERT INTO promises (debt_id, amount_cents, due_date, status)
                       VALUES (${debtId}, ${amountCents}, ${dueDate}, 'active')`);
}
```

La regla de negocio está mezclada con el SQL; probarla requiere una base con datos.

## Implementación correcta

```ts
// Dominio
export class Debt {
  constructor(
    readonly id: string,
    private balanceCents: number,
    private readonly promises: PaymentPromise[],
  ) {}

  promise(amountCents: number, dueDate: string): PaymentPromise {
    if (this.promises.some((p) => p.status === "active")) throw new DomainError("active-promise-exists");
    if (amountCents <= 0 || amountCents > this.balanceCents) throw new DomainError("invalid-amount");
    const promise: PaymentPromise = { id: crypto.randomUUID(), amountCents, dueDate, status: "active" };
    this.promises.push(promise);
    return promise;
  }

  get pendingPromises(): readonly PaymentPromise[] {
    return this.promises;
  }
}

// Puerto definido por la aplicación
export interface DebtRepository {
  findById(id: string): Promise<Debt | null>;
  save(debt: Debt): Promise<void>;
}

// Caso de uso: sólo orquesta
export async function registerPromise(
  repo: DebtRepository,
  input: { debtId: string; amountCents: number; dueDate: string },
) {
  const debt = await repo.findById(input.debtId);
  if (!debt) throw new DomainError("debt-not-found");
  const promise = debt.promise(input.amountCents, input.dueDate);
  await repo.save(debt);
  return promise;
}

// Implementación para tests
export class InMemoryDebtRepository implements DebtRepository {
  private readonly items = new Map<string, Debt>();
  async findById(id: string) {
    return this.items.get(id) ?? null;
  }
  async save(debt: Debt) {
    this.items.set(debt.id, debt);
  }
}
```

La implementación con PostgreSQL vive en infraestructura, mapea filas a `Debt` y se prueba con tests de
integración. Además, la base mantiene su propia defensa: un índice único parcial
(`CREATE UNIQUE INDEX ... ON promises(debt_id) WHERE status = 'active'`) evita dos promesas activas aunque dos
requests lleguen a la vez.

## Ejercicio

La bandeja del operador necesita listar 50 deudores con su saldo, última gestión y promesa activa, ordenados por
prioridad. ¿Lo agregarías al `DebtRepository` como `findAll()` y ordenarías en memoria?

<Reveal>

No. Cargar agregados completos para una pantalla es costoso y obliga a filtrar en memoria. Es una consulta de
lectura: conviene una función dedicada (por ejemplo `InboxQueries.list(tenantId, page)`) que ejecute un SQL
optimizado con paginación y devuelva un DTO plano. El repositorio queda para cargar y guardar agregados cuando hay
reglas que aplicar.

</Reveal>
