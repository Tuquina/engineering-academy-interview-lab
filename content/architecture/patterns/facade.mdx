## Motivación

El checkout de una tienda coordina inventario, impuestos, pago, factura y notificación. Lo usan la web, la app móvil y
un endpoint para revendedores.

## Ejemplo incorrecto

```ts
// En el handler web (y copiado en el móvil y en el de revendedores)
const reserved = await inventory.reserve(cart.items);
const taxes = await taxService.calculate(cart, address);
const charge = await paymentGateway.charge(customer.cardToken, cart.total + taxes.total);
const invoice = await invoicing.create(customer, cart, taxes, charge.id);
await mailer.send(customer.email, renderInvoice(invoice));
```

Cada cliente conoce el orden, maneja los errores a su manera y ninguno libera la reserva si el pago falla.

## Implementación correcta

```ts
export class CheckoutService {
  constructor(
    private inventory: Inventory,
    private taxes: TaxCalculator,
    private payments: PaymentGateway,
    private invoicing: Invoicing,
    private notifications: Notifications,
  ) {}

  /** Una operación con significado de negocio; los clientes no conocen los pasos. */
  async checkout(cart: Cart, customer: Customer): Promise<CheckoutResult> {
    const reservation = await this.inventory.reserve(cart.items);
    try {
      const taxes = await this.taxes.calculate(cart, customer.address);
      const charge = await this.payments.charge(customer.paymentMethod, cart.totalCents + taxes.totalCents);
      const invoice = await this.invoicing.create({ cart, customer, taxes, chargeId: charge.id });
      await this.notifications.invoiceIssued(customer, invoice); // idealmente asíncrono
      return { ok: true, invoiceId: invoice.id };
    } catch (error) {
      await this.inventory.release(reservation); // la compensación vive en un solo lugar
      throw error;
    }
  }
}
```

## Ejercicio

La fachada crece: ahora también aplica cupones, puntos de fidelidad y envío. ¿Cuándo deja de ser una buena idea y qué
harías?

<Reveal>

Cuando concentra **reglas de negocio** además de coordinar, o cuando partes distintas cambian por motivos distintos.
Opciones: mover las reglas al dominio (un agregado `Order` que calcula totales con cupones y puntos), dejar en la
fachada sólo la orquestación, y separar flujos (checkout, devoluciones) en casos de uso independientes. Si los pasos
cruzan servicios y pueden fallar a mitad, la coordinación pasa a ser una **saga**.

</Reveal>
