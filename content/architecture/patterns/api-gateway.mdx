## Motivación

Un marketplace tiene servicios de catálogo, precios, stock, reseñas y recomendaciones. La web y la app móvil muestran
la ficha de producto con datos de todos ellos.

## Ejemplo incorrecto

```ts
// En la app móvil: cinco requests, cinco formas de autenticar, cinco formatos.
const [product, price, stock, reviews, recs] = await Promise.all([
  fetch(`https://catalog.internal/products/${id}`, { headers: catalogAuth }),
  fetch(`https://pricing.internal/v2/prices?sku=${id}`, { headers: pricingAuth }),
  fetch(`https://stock.internal/availability/${id}`),
  fetch(`https://reviews.internal/products/${id}/reviews?page=1`),
  fetch(`https://recs.internal/similar?product=${id}`),
]);
```

## Implementación correcta

```ts
// BFF móvil: una request del cliente, agregación del lado del servidor.
app.get("/mobile/products/:id", requireUser, rateLimit, async (req, res) => {
  const id = req.params.id;
  const [product, price, stock] = await Promise.all([
    catalog.get(id), // los clientes internos tienen timeout y circuit breaker
    pricing.get(id, req.user.region),
    inventory.get(id),
  ]);
  // Lo opcional se degrada: si reseñas o recomendaciones fallan, la pantalla igual se muestra.
  const [reviews, similar] = await Promise.allSettled([reviewsClient.top(id, 3), recs.similar(id, 6)]);

  res.json({
    id,
    title: product.title,
    image: product.images[0]?.mobileUrl,
    price: price.formatted,
    inStock: stock.available > 0,
    reviews: reviews.status === "fulfilled" ? reviews.value : [],
    similar: similar.status === "fulfilled" ? similar.value : [],
  });
});
```

Delante de los BFF, el **API Gateway** termina TLS, valida el token, aplica rate limiting y enruta `/mobile/*` y
`/web/*` a cada BFF.

## Ejercicio

El servicio de precios responde lento (3 s) y la ficha de producto tarda lo mismo. ¿Qué cambiarías en el BFF?

<Reveal>

1. **Timeout** corto en la llamada a precios (por ejemplo, 300 ms) y **circuit breaker** para no seguir esperando a un
   servicio degradado.
2. **Fallback**: precio cacheado reciente con una marca de "precio a confirmar", o mostrar la ficha sin precio y
   cargarlo después desde el cliente.
3. **Caché** de precios por SKU y región con TTL corto en el BFF o en Redis.
4. Medir con trazas qué parte del tiempo es del servicio de precios y abrir el problema al equipo dueño.

</Reveal>
