## Motivación

Un servicio de reportes arma consultas de búsqueda de productos con filtros opcionales, orden, paginación por cursor y
un límite máximo. Algunas combinaciones no son válidas: no se puede paginar por cursor si no hay un orden estable.

## Ejemplo incorrecto

```ts
const query = new ProductSearch("zapatillas", null, ["running"], 20, null, "price", true, null);
// ¿Qué era el quinto parámetro? ¿El true es el orden descendente o "incluir sin stock"?
```

## Implementación correcta

```ts
export class ProductSearchBuilder {
  private filters: { category?: string; tags: string[] } = { tags: [] };
  private sort?: { field: "price" | "createdAt"; direction: "asc" | "desc" };
  private pageSize = 20;
  private cursor?: string;

  constructor(private readonly text: string) {}

  inCategory(category: string) {
    this.filters.category = category;
    return this;
  }
  withTags(...tags: string[]) {
    this.filters.tags.push(...tags);
    return this;
  }
  sortBy(field: "price" | "createdAt", direction: "asc" | "desc" = "asc") {
    this.sort = { field, direction };
    return this;
  }
  limit(size: number) {
    this.pageSize = size;
    return this;
  }
  after(cursor: string) {
    this.cursor = cursor;
    return this;
  }

  build(): Readonly<ProductSearch> {
    if (this.pageSize < 1 || this.pageSize > 100) throw new Error("El límite debe estar entre 1 y 100");
    if (this.cursor && !this.sort) throw new Error("Paginar por cursor requiere un orden estable");
    return Object.freeze({
      text: this.text,
      filters: { ...this.filters },
      sort: this.sort,
      pageSize: this.pageSize,
      cursor: this.cursor,
    });
  }
}

const search = new ProductSearchBuilder("zapatillas").withTags("running").sortBy("price").limit(20).build();
```

## Ejercicio

¿Cómo lograrías que el compilador impida llamar a `after()` sin haber llamado antes a `sortBy()`, en lugar de
validarlo en runtime?

<Reveal>

Con un **builder tipado por estado**: cada método devuelve un tipo distinto que sólo expone los métodos permitidos.

```ts
interface Unsorted {
  sortBy(field: SortField): Sorted;
  build(): ProductSearch;
}
interface Sorted {
  after(cursor: string): Sorted;
  build(): ProductSearch;
}
```

`after` sólo existe en `Sorted`, así que `new Builder("x").after("c")` no compila. Es más código: vale la pena en
librerías públicas donde el error de uso es frecuente.

</Reveal>
