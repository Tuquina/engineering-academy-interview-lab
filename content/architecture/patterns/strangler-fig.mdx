## Motivación

Un e-commerce funciona sobre un monolito de hace diez años. El equipo quiere un catálogo nuevo con búsqueda moderna y
un checkout más rápido, sin frenar las ventas ni arriesgar todo en un único corte.

## Ejemplo incorrecto

"Congelamos el monolito, reescribimos todo en microservicios durante 18 meses y hacemos el cambio un domingo a la
madrugada." Mientras tanto el negocio pide cambios que se hacen en los dos sistemas, el alcance crece y el día del corte
aparecen comportamientos del legado que nadie documentó.

## Implementación correcta

```text
Fase 1  Proxy delante del monolito: todo el tráfico pasa por él (sin cambios visibles).
Fase 2  /catalog/* → servicio de catálogo nuevo (lee productos sincronizados por CDC).
        Resto → monolito.
Fase 3  /search/* → servicio de búsqueda. Se compara el resultado con el legado en sombra (shadow traffic).
Fase 4  /checkout/* → servicio nuevo, primero para el 5 % de los usuarios (canary), luego 100 %.
Fase 5  El monolito sin tráfico se apaga; se elimina la sincronización.
```

```ts
// Regla de enrutamiento en el proxy (por ejemplo, un middleware o la configuración del gateway)
const migrated = [
  { prefix: "/catalog", target: CATALOG_URL },
  { prefix: "/search", target: SEARCH_URL },
  { prefix: "/checkout", target: CHECKOUT_URL, rollout: 0.05 },
];

function route(request: Request, userId: string): string {
  const rule = migrated.find((r) => new URL(request.url).pathname.startsWith(r.prefix));
  if (!rule) return LEGACY_URL;
  if (rule.rollout !== undefined && hashToUnit(userId) >= rule.rollout) return LEGACY_URL;
  return rule.target;
}
```

Cada fase se puede revertir cambiando una regla. Un **adaptador anticorrupción** traduce el modelo del legado al del
sistema nuevo para que sus conceptos no contaminen el diseño nuevo.

## Ejercicio

El servicio de checkout nuevo necesita los pedidos históricos, que siguen en la base del monolito. ¿Qué opciones tenés
y cuál elegirías al principio?

<Reveal>

1. **Leer del legado** mediante una API o vista del monolito (rápido para empezar; acopla al esquema viejo).
2. **Captura de cambios (CDC)**: replicar los pedidos a la base del servicio nuevo en casi tiempo real (desacopla
   lecturas; hay que manejar el lag).
3. **Migración + doble escritura** con verificación hasta que el nuevo sea la fuente de verdad.

Al principio, leer del legado detrás de un **adaptador anticorrupción** permite avanzar rápido; a medida que el
checkout gana tráfico conviene pasar a CDC y finalmente hacer que el servicio nuevo sea dueño de los pedidos.

</Reveal>
