## Motivación

Una API tiene decenas de endpoints que necesitan los mismos controles: correlation ID, logging, autenticación, rate
limiting y manejo uniforme de errores.

## Ejemplo incorrecto

```ts
export async function POST(request: Request) {
  const requestId = crypto.randomUUID();
  console.log(requestId, request.url);
  const user = await authenticate(request);
  if (!user) return Response.json({ error: "No autenticado" }, { status: 401 });
  if (!(await rateLimiter.allow(user.id)))
    return Response.json({ error: "Demasiadas requests" }, { status: 429 });
  try {
    // …lógica del endpoint
  } catch (e) {
    console.error(requestId, e);
    return Response.json({ error: "Error interno" }, { status: 500 });
  }
}
```

Copiado en cada endpoint, con pequeñas diferencias y algún control olvidado.

## Implementación correcta

```ts
type Context = { request: Request; requestId: string; user?: User };
type Handler = (ctx: Context) => Promise<Response>;
type Middleware = (ctx: Context, next: Handler) => Promise<Response>;

const withErrors: Middleware = async (ctx, next) => {
  try {
    return await next(ctx);
  } catch (error) {
    logger.error({ requestId: ctx.requestId, error });
    return Response.json({ error: "Error interno" }, { status: 500 });
  }
};

const withAuth: Middleware = async (ctx, next) => {
  const user = await authenticate(ctx.request);
  if (!user) return Response.json({ error: "No autenticado" }, { status: 401 }); // corta la cadena
  return next({ ...ctx, user });
};

const withRateLimit: Middleware = async (ctx, next) =>
  (await rateLimiter.allow(ctx.user!.id))
    ? next(ctx)
    : Response.json({ error: "Demasiadas requests" }, { status: 429 });

/** Compone los middlewares de afuera hacia adentro. */
export const chain =
  (...middlewares: Middleware[]) =>
  (handler: Handler) =>
  (request: Request) =>
    middlewares.reduceRight<Handler>(
      (next, mw) => (ctx) => mw(ctx, next),
      handler,
    )({
      request,
      requestId: request.headers.get("x-request-id") ?? crypto.randomUUID(),
    });

export const POST = chain(
  withErrors,
  withAuth,
  withRateLimit,
)(async ({ user }) => {
  return Response.json(await createOrder(user!));
});
```

## Ejercicio

¿En qué orden pondrías `withErrors`, `withAuth`, `withRateLimit` y un `withLogging` que registra método, ruta, status y
duración? Justificá.

<Reveal>

`withLogging` → `withErrors` → `withRateLimit` (por IP) → `withAuth` → (rate limit por usuario) → handler.

- **Logging** afuera de todo, para medir la duración total y registrar también las respuestas de error.
- **Errores** inmediatamente después, para que cualquier excepción de los siguientes se convierta en una respuesta
  uniforme.
- **Rate limit por IP antes de autenticar**: autenticar consulta la base y es caro; un atacante no debería poder
  forzar esas consultas sin límite. El límite por usuario va después de saber quién es.

</Reveal>
