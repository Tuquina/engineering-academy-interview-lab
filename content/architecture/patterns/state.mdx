## Motivación

Una promesa de pago tiene un ciclo de vida: se registra activa; puede cumplirse (llegó el pago), incumplirse (pasó
la fecha sin pago suficiente) o cancelarse (el deudor la reemplazó). Una promesa cumplida no puede volver a estar
activa y una cancelada no puede cumplirse.

## Ejemplo incorrecto

```ts
interface PaymentPromise {
  id: string;
  amountCents: number;
  dueDate: string;
  isFulfilled: boolean;
  isBroken: boolean;
  isCancelled: boolean;
  paidAt?: string;
  cancelReason?: string;
}

// En algún job:
promise.isBroken = new Date(promise.dueDate) < new Date();
// En el webhook de pagos:
promise.isFulfilled = true;
promise.paidAt = new Date().toISOString();
```

Nada impide una promesa `isFulfilled && isBroken`, ni que el job marque como incumplida una promesa cancelada.

## Implementación correcta

```ts
export type PaymentPromise =
  | { status: "active"; id: string; amountCents: number; dueDate: string }
  | { status: "fulfilled"; id: string; amountCents: number; dueDate: string; paidAt: string }
  | { status: "broken"; id: string; amountCents: number; dueDate: string; detectedAt: string }
  | { status: "cancelled"; id: string; amountCents: number; dueDate: string; reason: string };

export type PromiseEvent =
  | { type: "payment-received"; at: string }
  | { type: "due-date-passed"; at: string }
  | { type: "cancelled"; reason: string };

export class InvalidTransition extends Error {}

/** Única forma de cambiar el estado: pura, exhaustiva y fácil de probar como tabla. */
export function transition(promise: PaymentPromise, event: PromiseEvent): PaymentPromise {
  if (promise.status !== "active") {
    throw new InvalidTransition(`No se puede aplicar ${event.type} a una promesa ${promise.status}`);
  }
  const { id, amountCents, dueDate } = promise;
  switch (event.type) {
    case "payment-received":
      return { status: "fulfilled", id, amountCents, dueDate, paidAt: event.at };
    case "due-date-passed":
      return { status: "broken", id, amountCents, dueDate, detectedAt: event.at };
    case "cancelled":
      return { status: "cancelled", id, amountCents, dueDate, reason: event.reason };
  }
}
```

`paidAt` sólo existe en promesas cumplidas, y TypeScript obliga a verificar el estado antes de leerlo.

## Ejercicio

El negocio agrega un período de gracia: una promesa vencida pasa primero a `grace` durante 2 días; si llega el
pago en ese lapso se considera cumplida, si no, incumplida. ¿Qué cambia?

<Reveal>

Se agrega la variante `{ status: "grace"; ...; graceUntil: string }`. La transición `due-date-passed` desde
`active` ahora lleva a `grace`; desde `grace`, `payment-received` lleva a `fulfilled` y un nuevo evento
`grace-expired` lleva a `broken`. La guarda inicial deja de ser "sólo desde active" y pasa a validar por estado
(un `switch` sobre `promise.status` con otro anidado por evento). Los tests de tabla agregan las filas nuevas y
siguen verificando que las transiciones inválidas lancen error.

</Reveal>
