## Método STAR

| Parte         | Qué decir                                         | Peso aprox. |
| ------------- | ------------------------------------------------- | ----------- |
| **S**ituación | Contexto mínimo: equipo, producto, problema       | 15 %        |
| **T**area     | Tu responsabilidad concreta                       | 10 %        |
| **A**cción    | Qué hiciste **vos** y por qué, en primera persona | 50 %        |
| **R**esultado | Impacto medible y qué aprendiste                  | 25 %        |

Duración ideal: 2–3 minutos por historia. Terminar con el aprendizaje.

## Banco de historias (prepará 6–8)

Cada historia sirve para varias preguntas. Cubrí al menos:

- Un logro técnico del que estés orgulloso (con números).
- Un incidente en producción que ayudaste a resolver.
- Un error tuyo y qué cambiaste después.
- Un desacuerdo técnico y cómo se resolvió.
- Una vez que lideraste algo sin autoridad formal.
- Una entrega con plazo ajustado y cómo priorizaste.
- Una vez que aprendiste algo nuevo rápido.
- Una vez que ayudaste a crecer a alguien (mentoring, code review).

## Preguntas habituales

| Pregunta                                | Qué evalúan                         |
| --------------------------------------- | ----------------------------------- |
| Contame sobre vos                       | Síntesis y encaje con el puesto     |
| ¿Por qué esta empresa / este puesto?    | Interés real e investigación previa |
| El proyecto más desafiante              | Profundidad técnica y ownership     |
| Un conflicto con un compañero           | Colaboración y madurez              |
| Un error o fracaso                      | Responsabilidad y aprendizaje       |
| Una decisión con información incompleta | Criterio y manejo del riesgo        |
| Cómo priorizás cuando todo es urgente   | Organización y comunicación         |
| Feedback difícil que recibiste          | Apertura y crecimiento              |
| ¿Dónde te ves en unos años?             | Motivación y coherencia con el rol  |

## "Contame sobre vos" (plantilla de 90 segundos)

1. **Presente**: "Soy desarrollador backend con N años, hoy trabajo en… y me especializo en…"
2. **Pasado relevante**: 1–2 logros con impacto.
3. **Futuro**: "Busco… y este puesto me interesa porque…"

## CV técnico

- Una o dos páginas; lo más relevante primero.
- Cada bullet: **verbo + qué + cómo + resultado** ("Reduje el p95 de la API de 1,2 s a 250 ms agregando índices y caché en Redis").
- Tecnologías dentro de los logros, no sólo en una lista.
- Enlaces a GitHub o proyectos con README cuidado.
- Adaptar el resumen y el orden a cada búsqueda.

## Preguntas para hacer al final

- ¿Cómo es un día típico en el equipo?
- ¿Cómo se despliega a producción y quién está de guardia?
- ¿Qué haría que alguien en este puesto sea exitoso en los primeros 90 días?
- ¿Cuál es el mayor desafío técnico que tienen ahora?
- ¿Cómo son los procesos de code review y de feedback?

## Proceso completo

| Etapa                      | Cómo prepararte                                       |
| -------------------------- | ----------------------------------------------------- |
| Screening con recruiter    | Pitch de 90 s, expectativa salarial, disponibilidad   |
| Entrevista técnica teórica | Interview Arena: quick y deep dive                    |
| Live coding                | Problemas de algoritmos en voz alta, con tiempo       |
| Take-home                  | Código limpio, tests, README con decisiones           |
| System design              | Método por fases, practicar con diagramas             |
| Behavioral / cultural      | Banco de historias STAR                               |
| Oferta                     | Comparar paquete total; negociar con datos de mercado |
