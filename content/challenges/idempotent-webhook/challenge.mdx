## Contexto

El proveedor de pagos notifica cada pago con un webhook y garantiza entrega **al menos una vez**: si no recibe
un 2xx a tiempo, reenvía, y a veces envía el mismo evento dos veces en paralelo. Aplicar un pago dos veces marca como
pagado de más un pedido de una tienda, dispara un reembolso que no corresponde y le manda al cliente dos confirmaciones.

## Qué tenés que implementar

```ts
export interface PaymentEvent {
  eventId: string;
  orderId: string;
  amountCents: number; // entero > 0
}

export interface EventStore {
  wasProcessed(eventId: string): Promise<boolean>;
  markProcessed(eventId: string): Promise<void>;
}

export interface Ledger {
  applyPayment(orderId: string, amountCents: number): Promise<void>;
}

export type WebhookResponse =
  | { status: 200; body: { processed: true } | { processed: false; duplicate: true } }
  | { status: 400; body: { error: string } }
  | { status: 500; body: { error: string } };

export function createPaymentWebhookHandler(deps: {
  store: EventStore;
  ledger: Ledger;
}): (payload: unknown) => Promise<WebhookResponse>;
```

## Casos límite

- `amountCents` decimal, negativo o como string: inválido.
- Un evento cuyo procesamiento falló puede reintentarse con éxito.
- Eventos distintos se procesan de forma independiente (y pueden correr en paralelo).
