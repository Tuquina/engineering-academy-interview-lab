## Contexto

La API del proveedor de mensajería que usan los agentes falla de forma intermitente (timeouts, 503). Un reintento
inmediato suele volver a fallar y, si todos los clientes reintentan a la vez, empeoran la caída. La práctica estándar
es **reintentar con esperas que crecen exponencialmente**, con un tope y un número máximo de intentos.

## Qué tenés que implementar

```ts
export interface RetryOptions {
  retries: number; // reintentos además del primer intento
  baseDelayMs: number;
  maxDelayMs?: number; // por defecto, sin tope
  shouldRetry?: (error: unknown) => boolean; // por defecto, reintenta todo
  signal?: AbortSignal;
  sleep?: (ms: number) => Promise<void>; // por defecto, setTimeout
}

export function retry<T>(operation: (attempt: number) => Promise<T>, options: RetryOptions): Promise<T>;
```

`attempt` empieza en 1.

## Ejemplo

Con `retries: 3, baseDelayMs: 100, maxDelayMs: 250`: si fallan los intentos 1, 2 y 3, las esperas son 100, 200 y
250 ms (la tercera, acotada), y el intento 4 es el último.

## Casos límite

- `retries: 0` hace un único intento.
- Un error no recuperable (por ejemplo, un 400) se propaga sin esperar.
