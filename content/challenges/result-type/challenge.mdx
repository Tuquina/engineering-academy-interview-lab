## Contexto

Al registrar un pago manual, el operador escribe el monto como texto ("1500", "1500,50", "1.500,50"). Que el texto
sea inválido **no es excepcional**: es un caso esperable que la UI debe mostrar. Con excepciones, el compilador no
obliga a manejarlo; con un `Result` tipado, el error forma parte de la firma.

## Qué tenés que implementar

```ts
export type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };

export function ok<T>(value: T): Result<T, never>;
export function err<E>(error: E): Result<never, E>;
export function map<T, U, E>(result: Result<T, E>, fn: (value: T) => U): Result<U, E>;
export function andThen<T, U, E, F>(result: Result<T, E>, fn: (value: T) => Result<U, F>): Result<U, E | F>;
export function unwrapOr<T, E>(result: Result<T, E>, fallback: T): T;

export type AmountError = "empty" | "invalid-format" | "too-many-decimals" | "not-positive";
export function parseAmountCents(input: string): Result<number, AmountError>;
```

## Reglas de `parseAmountCents`

| Entrada      | Resultado                     |
| ------------ | ----------------------------- |
| `"1500"`     | `ok(150000)`                  |
| `"1500,5"`   | `ok(150050)`                  |
| `"1.500,50"` | `ok(150050)` (punto de miles) |
| `"  42,10 "` | `ok(4210)` (ignora espacios)  |
| `""`         | `err("empty")`                |
| `"12a"`      | `err("invalid-format")`       |
| `"10,999"`   | `err("too-many-decimals")`    |
| `"0"`        | `err("not-positive")`         |

La coma es el separador decimal y el punto, el de miles (formato habitual en Argentina).
