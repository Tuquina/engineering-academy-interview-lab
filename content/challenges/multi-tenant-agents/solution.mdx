## Una respuesta sólida

**Aislamiento.** Base compartida con `tenant_id` en todas las tablas y **Row Level Security** de PostgreSQL
(`SET app.tenant_id` por transacción y políticas `USING (tenant_id = current_setting('app.tenant_id')::uuid)`): un
olvido en un `WHERE` no filtra datos de otro tenant. Para bancos que lo exijan, la misma aplicación puede apuntar a
una **base dedicada** (modelo híbrido). Base por tenant para todos multiplica migraciones, conexiones y costos: no
compensa con un equipo chico.

**Modelo de configuración.**

```sql
agents (id, tenant_id, name)
agent_versions (
  id, agent_id, tenant_id, version_number,
  prompt, model, tools jsonb, policies jsonb,
  status text CHECK (status IN ('draft', 'published', 'archived')),
  created_by, created_at, published_by, published_at,
  UNIQUE (agent_id, version_number)
)
agent_deployments (agent_id PRIMARY KEY, active_version_id, updated_by, updated_at)
```

- Los borradores se editan; al **publicar**, la versión queda **inmutable**.
- `agent_deployments` apunta a la versión activa: **rollback** = cambiar el puntero (instantáneo, sin redeploy).
- Rollout gradual: la tabla de despliegue puede tener un porcentaje para una versión candidata.

**Conversaciones ligadas a una versión.** Cada conversación guarda `agent_version_id` al empezar y lo usa hasta el
final: un cambio de configuración no altera conversaciones en curso, y se puede reproducir cualquier decisión.

**Herramientas seguras.** El modelo sólo propone tool calls; el servidor valida los argumentos con un esquema, verifica
que la tool esté habilitada en esa versión y ejecuta con el `tenant_id` del contexto de la conversación (nunca con un
`tenant_id` que venga en los argumentos del modelo).

**Auditoría.** Eventos de publicación y rollback (quién, cuándo, diff entre versiones) y trazas por conversación:
mensajes, tool calls con argumentos y resultados, versión usada, costos y latencias.

**Escala.** Workers stateless consumen de una cola (mensajes entrantes, contactos programados) con concurrencia
limitada por tenant; configuraciones publicadas en caché (inmutables: invalidación trivial); rate limits hacia los
proveedores de LLM y fallback de modelo.

**Calidad.** Publicar exige pasar una suite de **evals** de la versión candidata (casos de cumplimiento, tool calling
correcto, tono) con un umbral: un quality gate antes de producción.
