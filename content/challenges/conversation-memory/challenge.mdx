## Contexto

Un agente de IA de un hotel habla con un huésped el día 1 y le **retiene una habitación** hasta el día 15, a la espera de
la seña. El día 5, el orquestador de avisos intenta incluirlo en una campaña de "completá tu reserva". Si el agente lo
contacta, el huésped recibe un mensaje que contradice lo acordado: mala experiencia y, si el aviso insiste, un
reclamo.

La decisión no debe depender de lo que "recuerde" el modelo en su contexto, sino del **estado del negocio**
reconstruido a partir de eventos: reservas retenidas, pagos, intentos de contacto y reclamos.

## Qué tenés que implementar

```ts
export type MemoryEvent =
  | { type: "hold-created"; at: string; dueDate: string; amountCents: number }
  | { type: "hold-cancelled"; at: string }
  | { type: "payment-received"; at: string; amountCents: number }
  | { type: "contact-attempt"; at: string }
  | { type: "complaint-opened"; at: string };

export type ContactDecision =
  | { action: "contact"; strategy: "standard" | "deposit-reminder" | "deposit-overdue"; reason: string }
  | { action: "wait"; reason: string }
  | { action: "do-not-contact"; reason: string };

export function decideNextContact(events: readonly MemoryEvent[], today: string): ContactDecision;
```

## Ejemplo

| Eventos                                   | Hoy        | Decisión                          |
| ----------------------------------------- | ---------- | --------------------------------- |
| Reserva el 01, seña de $1.500 hasta el 15 | 2026-03-05 | `wait` (reserva retenida vigente) |
| (igual)                                   | 2026-03-14 | `contact` / `deposit-reminder`    |
| (igual), sin pagos                        | 2026-03-16 | `contact` / `deposit-overdue`     |
| (igual) + pago de $1.500 el 12            | 2026-03-16 | `wait` (seña pagada)              |
