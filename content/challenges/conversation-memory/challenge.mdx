## Contexto

Un agente de IA de cobranzas habla con un cliente el día 1 y obtiene una **promesa de pago** para el día 15. El día 5,
el orquestador de campañas intenta incluirlo en una campaña nueva. Si el agente lo contacta, el cliente recibe un
mensaje que contradice lo acordado: mala experiencia y, en algunos mercados, un problema regulatorio.

La decisión no debe depender de lo que "recuerde" el modelo en su contexto, sino del **estado del negocio**
reconstruido a partir de eventos: promesas, pagos, intentos de contacto y disputas.

## Qué tenés que implementar

```ts
export type MemoryEvent =
  | { type: "promise-made"; at: string; dueDate: string; amountCents: number }
  | { type: "promise-cancelled"; at: string }
  | { type: "payment-received"; at: string; amountCents: number }
  | { type: "contact-attempt"; at: string }
  | { type: "dispute-opened"; at: string };

export type ContactDecision =
  | { action: "contact"; strategy: "standard" | "promise-reminder" | "broken-promise"; reason: string }
  | { action: "wait"; reason: string }
  | { action: "do-not-contact"; reason: string };

export function decideNextContact(events: readonly MemoryEvent[], today: string): ContactDecision;
```

## Ejemplo

| Eventos                             | Hoy        | Decisión                       |
| ----------------------------------- | ---------- | ------------------------------ |
| Promesa el 01 para el 15 por $1.500 | 2026-03-05 | `wait` (promesa vigente)       |
| (igual)                             | 2026-03-14 | `contact` / `promise-reminder` |
| (igual), sin pagos                  | 2026-03-16 | `contact` / `broken-promise`   |
| (igual) + pago de $1.500 el 12      | 2026-03-16 | `wait` (promesa cumplida)      |
